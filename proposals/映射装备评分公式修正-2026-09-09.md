# Proposal: 映射装备评分公式修正

**提案编号:** PROP-20260909-EEQUIP-SCORE
**日期:** 2026-09-09
**作者:** 数值/策划 Agent（与用户对话共同定稿）
**状态:** 草案
**相关 Design:** `numerical-workflows/v2/framework/03_沉淀MD/养成/映射装备养成数值沉淀-2026-07-07.md`（主属性曲线口径）

---

## 1. 背景与目标

### 1.1 问题

现行映射装备评分（服务端计算、经 `proto.cmsg.SEEquipment.score` 下发）：

```text
装备评分 = A × 等级上限 × 品质系数 + B × Σ词条评分
A = SpecialEquipmentScoreA = 20，B = SpecialEquipmentScoreB = 1.25
（globals_conf.xlsx 第 158/159 行）
```

存在结构性缺陷，实测出现"属性全面更高的装备评分反而更低"（截图案例：蓝装
千湖项链 Lv25 评分 494，低于蓝装旅行者项链 Lv15 的 632）：

1. **等级不参与评分**：静态项 `A×等级上限×品质系数` 只看品质对应 GradeLimit，
   与装备当前等级无关；而等级→属性是 **1.35 次幂凸曲线**
   （等级倍率 = 0.05 + 0.95×((等级-5)/55)^1.35，见主属性设计公式），线性/静态的
   评分无法反映等级背后的真实属性量。
2. **词条分与数值脱钩**：词条评分按"所属档位上限归一化"处理时，低级词条贴着
   低档上限拿高分（旅行者能量回复 122/122.33≈100%），高级词条绝对值大但占比低
   （千湖暴伤 251/385.8≈65%），跨等级比较完全失真。
3. **主属性不计分**：主属性承载了品质系数（GradeCoefficient）与非线性等级成长，
   却不进入评分。
4. **双重计品质**：静态项（品质系数）与词条基础分（分品质）重复表达品质，
   口径混乱。

### 1.2 危害

评分是"一键穿戴"与红点提示的唯一排序依据
（客户端 `MappingEquipSystem.lua:1597`：等级/品质/评分任一更高即推荐替换；
引导文案"一键穿戴评分较高的装备"）。评分失真会直接引导玩家穿上更差的装备，
属于 gameplay 层面的实际误导。

### 1.3 目标

- **定位 A（已与用户确认）**：评分 = 装备属性价值的总和，用于"哪件更好"的排序。
- 评分随等级（沿 1.35 曲线）、品质（经主属性 GradeCoefficient）、词条 roll 值
  **单调不减**；跨等级、跨品质可比。
- 公式不带任何整体缩放系数（已确认去掉 K），评分即属性分的直接取整。
- 服务端只改评分函数，**零表结构变更**（新增 1 张定价小表除外）。

## 3. 落地方案

### 3.1 设计变更：新评分公式

```text
第一步：属性单价表（新增配置，第一手策划资产，全局固定）
  UnitPrice(属性a) = 该属性每 1 点（百分比属性每 1%）的评分价值
  锚点：共享参数基线「属性定价」表（1%攻击当量口径，2026-09-09 裁决采用）
  - 平面：标准人 1%攻=15点攻 / 1%防=10点防 / 1%血=50点血
    → 每点 攻击1.0 / 防御1.5 / 生命0.3
  - 百分比：定价表三系同价（每1%=15分）× **0.5 平衡系数 = 7.5 分**
    （2026-09-09 确认：词条投放维持旧表不动，而旧投放下等级类词条在低中等级段
    相对 %词条偏差中位 1.92×，%单价减半使中位档竞争回归中性；属平衡性微调）
  - 等级类：暴击90/暴伤110/能量90/冷却130 点=1%攻当量 → 每点 = 15/N 分
  （初版曾按 Effect 表 Score÷ValueMax 派生播种，交叉验证发现等级类与定价表
   相差 15~20 倍，实战对照（旅行者腰带 vs 千湖礼仪腰带）支持定价表口径，
   已整体改锚，见 §3.4(b)4）

第二步：装备评分
  装备评分 = round( Σ主属性(最终主属性值 × UnitPrice)      ← 品质（GradeCoefficient）与
                                                     非线性等级成长经主属性自然进入
                        + Σ数值词条(词条数值 × UnitPrice)  ← 普通/稀有词条同口径
                        + Σ技能词条( Effect表Score，直接读取 ) )  ← 技能类词条不参与属性
                                                     计算，直接读词条配置的评分基础值
```

技能词条说明：技能类词条（3 万段 ID）的数值是"效果强度"而非属性值，与
属性单价不同质，**不做数值换算，直接读 `SpecialEquipmentEffect.xlsx#Score`
（当前统一 150）作为该词条得分**。理由：① 技能强度 roll 区间小
（金 100%~120%、红 120%~140%），缩放收益有限；② 强度区间当前无配置承载，
按比例计分需先补配 ValueMin/ValueMax，改动面大；③ 直接读 Score 零新增配置、
零表结构变更，后续若需要强度细分化再单独立项。

不设全局缩放系数（K 已确认去掉）：评分 = 属性分直接取整，语义最干净；
"属性间相对价值"由单价表表达，无第二个旋钮。

废弃：`装备评分 = 20×等级上限×品质系数 + 1.25×Σ词条评分` 整体退役；
`SpecialEquipmentScoreA/B` 字段退役。

设计要点（与用户逐条确认过的决策）：

| 决策点 | 结论 |
|---|---|
| 评分定位 | A：属性总量排序器（一键穿戴/红点的语义与之绑定） |
| 等级因子 | 直接继承主属性 1.35 次幂曲线，不做线性近似 |
| 主属性 | 计分，与词条按"属性"同价（同属性主/副同价，战斗价值一致） |
| 品质因子 | 不单独设品质项：品质经主属性 GradeCoefficient 与词条数值自然体现 |
| 技能型词条 | 直接读 Effect 表 Score（固定分，不随 roll 缩放）；属性词条按单价×数值计 |
| 单价来源 | 显式配置表；锚定共享参数基线「属性定价」，百分比三系×0.5 平衡系数 |
| 全局缩放 | **不设 K**，评分即属性分取整 |

### 3.2 配置变更

**（a）新增 `SpecialEquipment/SpecialEquipmentScorePrice.xlsx`**（Luban 表，schema 建议）：

| 字段 | 类型 | 说明 |
|---|---|---|
| Id | int | 主键 |
| Attribute | string | 属性类型（与 Effect 表 Attribute 同键；主属性复用同键） |
| UnitPrice | float | 每 1 点单价；百分比属性按"每 1%"计价（5.4% 记 5.4×单价） |

**（b）globals_conf 新增/退役字段**：

| 字段 | 类型 | 说明 | 初始值 |
|---|---|---|---|
| SpecialEquipmentScoreA / B | — | **退役**（保留字段位一个版本后删除） | — |

> 技能词条得分直接读 `SpecialEquipmentEffect.xlsx#Score`（当前统一 150），
> 不需要新增全局参数。

**（c）单价表播种值**（锚点：共享参数基线「属性定价」表，2026-09-09 定稿；
已落镜像 `06_最终配置/映射装备/SpecialEquipmentScorePrice.xlsx`）：

| 属性 | 换算依据 | UnitPrice |
|---|---|---|
| Attack（平面） | 1点攻 = 1分（基准） | 1.0 |
| Armor（平面） | 10点防=1%攻 → 每点 1.5 分 | 1.5 |
| Hp（平面） | 50点血=1%攻 → 每点 0.3 分 | 0.3 |
| AttackBonus / ArmorBonus / HpBonus | 定价表每1%=15点攻当量 × 0.5 平衡系数 | **7.5** /1% |
| CritLevel / EnergyPreAddBonusLevel | 90点 = 1%攻 | 0.166667 /点 |
| CritDmgBonusLevel | 110点 = 1%攻 | 0.136364 /点 |
| CoolDownReduceLevel | 130点 = 1%攻 | 0.115385 /点 |

> 等级类换算系数（90/110/130）出自共享参数基线「属性定价」表；其战斗换算
> 基准（等级→%的 rating 曲线是否随玩家等级缩放）建议战斗组复核。若复核
> 有变，只需改单价表数值，公式不动。

**（d）主属性计算口径（不变，引用自既有沉淀）**：

```text
程序主属性原值 = Value × Grow^(装备等级/5) + Param
最终主属性     = 程序原值 × GradeCoefficient
（Value=T×0.6238763, Grow=1.0830838, Param=T×(-0.6257103)，T=60级红装目标值）
```

### 3.4 验证方式

**（a）实算样例（提案评审用，全部代入播种单价）**

单价：攻击平面 1.0/点、防御 1.5/点、生命 0.3/点、百分比 **7.5/1%**（定价表
15×0.5 平衡系数）、暴击/能量 0.166667/点、暴伤 0.136364/点、冷却 0.115385/点。

**样例 1：截图反例修正**

| 装备 | 算式 | 评分 | 旧评分 |
|---|---|---|---|
| 旅行者项链（蓝 Lv15：主暴伤661+暴伤150+能量122+生命5.9%） | 661×0.136364 + 150×0.136364 + 122×0.166667 + 5.9×7.5 = 90.1+20.5+20.3+44.3 = 175.2 | **175** | 632 ❌ |
| 千湖项链（蓝 Lv25：主暴伤803+暴伤251+生命5.4%+防御5.4%） | 803×0.136364 + 251×0.136364 + 5.4×7.5 + 5.4×7.5 = 109.5+34.2+40.5+40.5 = 224.7 | **225** | 494 ❌ |

新公式 225 > 175 ✓，反例修正。

**样例 1b：腰带对照（等级类单价的裁决用例）**

| 装备 | 算式 | 评分 |
|---|---|---|
| 旅行者腰带（蓝 Lv20：主防262+能量190+生命6.4%+攻击6.4%） | 262×1.5 + 190×0.166667 + 6.4×7.5 + 6.4×7.5 = 393.0+31.7+48.0+48.0 | **521** |
| 千湖礼仪腰带（Lv25：主防228+防御171+暴伤251+冷却297） | 228×1.5 + 171×1.5 + 251×0.136364 + 297×0.115385 = 342.0+256.5+34.2+34.3 | **667** |

旧公式 727 vs 392 差近一倍 ❌；新公式 521 vs 667。千湖高 28%，主因是它携带
171 点平面防御（当前投放口径下平面词条是最强词条，关联"平面 7.5×"待裁决项）。

**样例 1c：手枪（%削减效果）**

旅行者手枪（蓝 Lv20：主攻524+暴伤125+防御3.5%）= 524×1.0 + 125×0.136364
+ 3.5×7.5 = 524.0+17.1+26.3 = **567**。

**样例 2：红装 60 级满 roll 武器（量级锚点）**

```text
主攻击 11250×1.0 + 暴伤满roll 2533.3×0.136364 + 能量满roll 2072.7×0.166667
       + 攻击%满roll 23.03×7.5 + 防御满roll 1727.6×1.5
= 11250 + 345.5 + 345.5 + 172.7 + 2591.4 = 14705（满roll组合不同在 1.3万~1.6万 浮动）
```

**样例 3：等级单调性（同品质蓝项链，同 roll 比例）**

| 等级 | 评分 |
|---|---|
| Lv15 | 175 |
| Lv25 | 353 |
| Lv30（蓝上限） | 456 |

升级必涨分 ✓，涨幅继承 1.35 次幂曲线。

**样例 4：技能型词条**

```text
直接读 Effect 表 Score = 150 分/条（红装满 roll 与低 roll 同分，强度细分不在本期范围）
```

**（b）回归门禁（实施前必须全绿）**

1. **单调性**：全品质 × 等级 5~60 × roll 0~100% 全组合：
   同部位同品质下，等级更高且每条词条数值都不更低的装备，评分严格更高。
   （回归脚本由数值工作流产，覆盖 5 品质 × 12 等级档 × 10 属性。）
2. **截图反例回归**：样例 1 两件装备的配置还原用例，纳入常驻回归。
3. **量级锚点**：红 60 满 roll 单件评分落在 1.3万~1.6万。
4. **单价来源锚定**：UnitPrice 以共享参数基线「属性定价」表为唯一锚点
   （2026-09-09 裁决）。初版按 Effect 表 Score÷ValueMax 派生的口径已废弃——
   交叉验证发现等级类相差 15~20 倍、百分比相差 2 倍以上，且腰带实战对照
   （样例 1b）支持定价表口径。Effect 表 Score 仅保留技能词条直读职责。

## 4. 风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| 服务端实际词条分算法与本提案反推不一致 | 中 | 修改靶点偏移 | 实施前由服务端确认现行 `SEEffectAttr.score` 算式与本提案 §1.1 的反推（档位上限归一化）核对 |
| 红档 Score/ValueMax 池映射细节与本提案假设有出入 | 低 | 不再影响单价 | 单价已改锚属性定价表，与 Effect 表解耦；该风险仅剩技能词条直读 Score（数值即配置） |
| 存量评分重算引发排行榜/战力展示跳变 | 高 | 玩家感知 | 新分数区间与旧分数同量级（腰带案例：521/667 vs 旧 392/727），属一次性全量重置，与版本公告同步 |
| %词条单价减半后，低等级段一键穿戴偏保守（%词条实际投放更强） | 中 | 推荐非最优 | 已知取舍：投放维持旧表前提下的平衡选择；若后续落地词条投放对齐（CHG027 搁置方案），恢复 % 单价至定价表原值即可 |
| 等级类换算系数（90/110/130）的战斗基准过时 | 中 | 等级类词条评分失真 | 建议战斗组复核 CritLevel→暴击率的 rating 曲线；若有变只改单价表数值 |
| 一键穿戴行为大面积变化（推荐结果改变） | 高 | 预期内 | 这正是本提案目的；灰度期观察替换率与玩家反馈 |
| 百分比单位歧义（每1% vs 每单位小数）导致 100 倍误差 | 中 | 严重 | 表 schema 注释强制"每1%"；回归脚本断言量级 |
