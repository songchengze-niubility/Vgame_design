# 数值框架 V2

数值框架已完整纳入项目策划框架，分为共享底座、养成、战斗、经济资源、节奏开放、概率随机、奖励掉落、商业化运营和验算配置交付九域。任何数值结论必须写明目标体验、公式/参数、输入来源、输出消费者、风险边界和验证方法。

专业正文：`domains/M02-数值框架v2专业正文.md`；原子注册与按需查询入口：`numerical/README.md`。生产源码、可编辑输入与正式数值文档：`numerical-workflows/v2/`；44 份正式 Excel 位于 `numerical-workflows/v2/framework/04_数值文档/`；机器清单：`numerical-workflows/v2/workflow-manifest.json`。旧外部数值源只作为迁移证据，正式正文、知识重建及数值生产不依赖旧数值盘。

生产链由 Git 管理的 59 个脚本、37 份数值设计输入工作簿、参数 MD 和 44 份正式交付 Excel 构成。源表拥有字段必须先回写 Git 管理的参数 MD，再同步知识库机器参数注册表；执行 `python scripts/numerical-workflows/run_production.py` 时，先在 `output/numerical-production-workflow-v2/` 创建全新隔离 staging，再检查源表与权威 MD 零差异、执行 2 个输入门禁、22 个生成任务、44 份终稿组装和 6 项独立动态验算，不会在 staging 中覆盖参数权威。全部门禁通过后，才整体替换 `numerical-workflows/v2/framework/04_数值文档/`；运行过程、验算报告与历史归档继续只写 `output/`，任何失败均不得覆盖正式交付。

真实项目 Datas 仍由 `VGAME_CONFIG_DATAS` 提供，并只作配置回源；这不等于依赖旧数值盘，也不允许自动写入 SVN 正式表。专武源页虽已移除，但裁决 B 的兼容期继续使用参数 MD 中已沉淀的专武数据；缺少公式缓存时保留已确认节奏 MD，不用空值覆盖。

权威链：`策划目标与系统契约 → 数值原子/公式/参数 → 源表与配置候选 → 模拟与验算 → 配置镜像 → 人工批准 → Datas/Luban/回执`。镜像与验算通过不等于 Production/LIVE。

房车最新规则为 +30/+60/+100、权重 50/30/20；专武保留一个大版本兼容迁移期。两项均是已批准目标，不能反推当前工作副本已经实施。
