# 温泉系统 — 策划配置表结构

## 元信息

| 项 | 内容 |
|----|------|
| 功能名称 | 温泉（社交互动场景） |
| 来源需求 | 需求方本机桌面文件《Vgame 温泉.xlsx》（提供人：hanyongkui；功能需求 + 场景需求） |
| 创建日期 | 2026-07-14 |
| 状态 | `Draft` |
| 配置表根目录 | `${VGAME_ROOT}\Config\GameConfig\Datas\Hotspring\`（建议） |

## 需求要点速览

| 维度 | 要点 |
|---|---|
| 设计目的 | 增加玩家可互动场景，增强社交交流 |
| 开放条件 | 开服第 2 天 |
| 核心循环 | 拖小人入温泉 → 计时 → 领体力/经验；邀请好友 → 好友泡汤 → 邮件发体力 |
| 体力回复 | 每日 1 次，仅 14:00–24:00，必须手动拖入触发 |
| 好友参与 | 每日领 1 次参与奖励；可帮多人但只领 1 次；奖励邮件 48H |
| 并发限制 | 邀请多位好友，但需上一轮温泉结束才能邀下一位 |
| 小人 | 默认可选：主角、小寒、陈单单、夏提拉；好友进入随机 |
| 场景上限 | 同时 5 个小人 |

## 配置表清单

| # | 表名（建议） | 文件名（建议） | 用途 | 行规模 |
|---|---|---|---|---|
| T1 | 温泉全局配置 | `HotspringGlobal.xlsx` | 全局参数（开放、时间窗、上限、邮件） | 单行 |
| T2 | 温泉小人配置 | `HotspringCharacter.xlsx` | 可显示/随机的小人模型与开关 | 多行 |
| T3 | 温泉区域配置 | `HotspringArea.xlsx` | 木板/水域坐标与自动进入概率 | 多行 |
| T4 | 温泉奖励配置 | `HotspringReward.xlsx` | 体力/经验/好友参与奖励与计时 | 多行 |
| T5 | 温泉邀请配置 | `HotspringInvite.xlsx` | 邀请并发数、时长、状态枚举映射 | 单行/少行 |

> 关联已有表：奖励内容通过 `DropId` 关联 Drop 表；开放条件可关联 `SystemOpen`；邮件模板关联邮件配置表；红点关联红点配置表。

## T1. 温泉全局配置表 `HotspringGlobal.xlsx`

> 单行表，存放整个温泉系统的全局开关与阈值。

| 行 | 字段 | 类型 | group | 说明 |
|---|---|---|---|---|
| `##var` | Id | int | server | 配置 ID，固定 1 |
| | OpenDay | int | server | 开放日期（开服第 N 天），需求=2 |
| | StaminaRecoverDailyLimit | int | server | 体力回复每日触发上限，需求=1 |
| | StaminaRecoverStartHour | int | server | 体力回复生效开始小时（24h 制），需求=14 |
| | StaminaRecoverEndHour | int | server | 体力回复生效结束小时（24h 制），需求=24 |
| | MaxCharacterCount | int | server | 场景同时存在小人上限，需求=5 |
| | MailDurationHours | int | server | 奖励邮件持续时间（小时），需求=48 |
| | FriendJoinRewardDailyLimit | int | server | 好友每日领取参与奖励上限，需求=1 |
| | AutoEnterValidForStamina | bool | server | 自动进入是否触发体力回复，需求=false（仅手动） |
| | UnclaimedResendNextDay | bool | server | 当日未领体力是否次日邮件补发，需求=true |
| | ConfirmDialogOncePerDay | bool | server | 当日触发后再次拖入是否不再弹确认窗，需求=true |
| | EntranceRedDotId | int | client | 主城入口红点映射 ID（可领体力时亮） |

**待确认**：
- 未领体力「次日邮件补发」的具体补发时间点（次日 0 点？次日 14 点？）。
- 红点是否复用现有红点配置表 ID 体系。

## T2. 温泉小人配置表 `HotspringCharacter.xlsx`

> 可在温泉场景中显示的小人列表，含主角与伙伴。

| 行 | 字段 | 类型 | group | 说明 |
|---|---|---|---|---|
| `##var` | CharacterId | int | server | 小人 ID |
| | CharacterName | string | both | 小人名称（主角/小寒/陈单单/夏提拉） |
| | ModelRes | string | client | 通用模型资源路径 |
| | WalkAnimRes | string | client | 走动动作资源 |
| | SoakAnimRes | string | client | 泡汤动作资源 |
| | IsDefaultSelectable | bool | server | 是否默认可选（初版主角等 4 人=true） |
| | InFriendRandomPool | bool | server | 是否在好友进入随机池中 |
| | Order | int | client | 列表排序权重 |

**待确认**：
- 「主角」小人是否区分性别（通用男/女），需否拆两行或加 Gender 字段。
- 伙伴小人随养成解锁是否在本表用 Unlock 字段控制，还是由伙伴系统过滤。

## T3. 温泉区域配置表 `HotspringArea.xlsx`

> 场景内木板与温泉水域的区域定义，供寻路与自动进入判定。

| 行 | 字段 | 类型 | group | 说明 |
|---|---|---|---|---|
| `##var` | AreaId | int | server | 区域 ID |
| | AreaType | enum | server | 区域类型：`Board`（木板/岸）/`Water`（温泉水域） |
| | AutoEnterProbability | float | server | 小人走到木板附近自动进入温泉概率（0–1） |
| | CenterX | float | client | 区域中心 X 坐标 |
| | CenterZ | float | client | 区域中心 Z 坐标 |
| | RangeX | float | client | 区域范围 X（半宽） |
| | RangeZ | float | client | 区域范围 Z（半长） |
| | MoveMode | enum | server | 移动方式：`Line`（线）/`Area`（区域） |

**说明**：
- `AutoEnterProbability` 仅影响「自动进入泡汤领经验」行为；体力回复必须手动拖入，不受此概率影响。
- 坐标字段建议由场景/关卡侧填入，策划确认范围。

## T4. 温泉奖励配置表 `HotspringReward.xlsx`

> 不同触发场景下的奖励内容、所需计时、每日上限。

| 行 | 字段 | 类型 | group | 说明 |
|---|---|---|---|---|
| `##var` | RewardId | int | server | 奖励 ID |
| | RewardType | enum | server | 奖励类型：`SelfStamina`（自身体力）/`SelfExp`（自身经验）/`FriendJoinStamina`（好友参与体力） |
| | TriggerType | enum | server | 触发方式：`ManualDrag`（手动拖入）/`AutoEnter`（自动进入）/`FriendJoin`（好友参与） |
| | RequiredTime | int | server | 进度条所需时间（秒），满后可领 |
| | DropId | int | server | 奖励掉落 ID（关联 Drop 表） |
| | DailyLimit | int | server | 每日领取上限 |
| | DeliverByMail | bool | server | 是否邮件发放（好友参与=true） |

**示例行（待数值确认）**：

| RewardId | RewardType | TriggerType | RequiredTime | DropId | DailyLimit | DeliverByMail |
|---|---|---|---|---|---|---|
| 1 | SelfStamina | ManualDrag | 待定 | 待定 | 1 | false |
| 2 | SelfExp | AutoEnter | 待定 | 待定 | — | false |
| 3 | FriendJoinStamina | FriendJoin | 待定 | 待定 | 1 | true |

**待确认**：
- 经验奖励是否有每日上限（需求未明确）。
- `RequiredTime` 体力与经验的具体秒数。
- 好友参与的 `RequiredTime` 是否与自身相同。

## T5. 温泉邀请配置表 `HotspringInvite.xlsx`

> 邀请好友相关的并发、时长与状态。

| 行 | 字段 | 类型 | group | 说明 |
|---|---|---|---|---|
| `##var` | Id | int | server | 配置 ID，固定 1 |
| | MaxConcurrentInvite | int | server | 同时可邀请好友数（需求=多位，但串行） |
| | SequentialInvite | bool | server | 是否需上一轮温泉结束才能邀下一位，需求=true |
| | SessionDuration | int | server | 单轮温泉邀请时长（秒） |
| | OutOfTimePromptId | int | client | 非活动时间点击邀请的提示文案 ID |
| | StateReceivable | int | server | 状态枚举值：可接收 |
| | StateOccupied | int | server | 状态枚举值：占用中 |
| | StateInvalid | int | server | 状态枚举值：失效 |

**待确认**：
- `SessionDuration` 单轮时长具体秒数。
- `MaxConcurrentInvite` 是否真为「同时多人」还是实际只能 1 人（需求表述「同时只能邀请多位好友，但是只有温泉结束后方可邀请第二位」存在矛盾，需澄清）。

## 关联关系图

```
HotspringGlobal ──┬──> SystemOpen（开放第2天）
                  ├──> 红点配置表（EntranceRedDotId）
                  └──> 邮件模板表（MailDurationHours）

HotspringReward ──┬──> Drop 表（DropId 发体力/经验）
                  └──> 邮件模板表（好友参与 DeliverByMail）

HotspringCharacter ──> 伙伴/角色系统（解锁与模型）

HotspringArea ──> 场景/关卡坐标
```
