## 背景与目标

### 背景

当前关卡结算奖励主要来自关卡配置的固定/随机 Drop。部分关卡局内会产生金币或金币类拾取物，但如果局内表现无法转化为局外收益，玩家对“多打、多捡、多优化路线”的感知较弱。

本功能允许策划配置指定关卡类型支持“局内金币带出”，并为每个关卡配置带出倍率。玩家通关后，服务器根据本局局内金币获得量计算额外局外金币奖励，并记录该玩家在该关卡的历史最高局内金币表现。玩家后续扫荡该关卡时，可基于历史最高记录获得额外金币。

### 目标

让支持该功能的关卡形成“手动挑战刷最好记录，扫荡按最好记录补发额外金币”的轻量循环。

### 非目标

- 本期不改变现有 Drop/UIlevel 的基础通关奖励。
- 本期不设计新的金币消耗口。
- 本期不做排行榜、赛季重置或跨玩家比较。
- 本期不把所有关卡默认纳入带出，只由配置显式开启。
- 本期不支持失败、退出或未成功结算时带出局内金币。

## 核心规则

### R-01: 关卡类型可配置开启

- **触发条件**：玩家完成一次关卡结算，且该关卡所属 `LevelType` 被配置为支持局内金币带出。
- **前置限制**：关卡必须存在有效关卡配置；未开启的关卡类型不计算、不展示、不记录。
- **操作流程**：
  1. 服务器读取关卡 `LevelId` 与 `LevelType`。
  2. 判断 `LevelType` 中的局内金币带出开关是否开启。
  3. 未命中则走原有结算逻辑。
  4. 命中后继续读取 `UIlevel` 中该 `LevelId` 的带出倍率和单次上限。
- **状态变化**：无玩家状态变化，仅进入带出计算分支。
- **资源变化**：本规则本身不发奖。
- **UI 反馈**：未开启类型不展示“局内金币带出”相关信息。
- **异常边界**：`LevelType` 开启但 `UIlevel` 关卡倍率缺失时，按 0 倍处理并记录配置告警。
- **落地点**：`LevelType.xlsx`、`UIlevel.xlsx`、服务器结算逻辑、QA 配置检查。

### R-02: 按关卡倍率计算可带出金币

- **触发条件**：关卡类型已开启，玩家本次手动挑战成功结算。
- **前置限制**：仅通关成功时发放带出金币；失败、退出、断线未结算不发放。
- **操作流程**：
  1. 玩家在场景内拾取局内金币，客户端累计本局局内金币获得量。
  2. 客户端在战斗结算协议中上报本局局内金币获得量，客户端与服务端共同核对字段含义与计数口径。
  3. 服务器读取该 `LevelId` 的 `CarryOutMaxGold` 和 `CarryOutRatio`。
  4. 服务器先对上报值做单次上限裁剪：`有效局内金币 = min(上报局内金币, CarryOutMaxGold)`。
  5. 计算：`本次额外金币 = floor(有效局内金币 * CarryOutRatio)`。
  6. 将额外金币合并到关卡结算奖励中发放。
- **状态变化**：若有效局内金币高于历史最高，更新该玩家该关卡的最高记录。
- **资源变化**：增加局外金币货币，`ItemId = 1`。
- **UI 反馈**：结算页在原有关卡奖励外增加“局内带出”金币条目。
- **异常边界**：
  - 局内金币获得量小于 0 时按 0 处理。
  - 带出倍率小于 0 时配置非法；运行时按 0 处理。
  - 上报值超过 `CarryOutMaxGold` 时，只按 `CarryOutMaxGold` 参与计算和历史记录刷新。
- **落地点**：关卡结算服务、奖励发放、`UIlevel.xlsx`、结算 UI。

### R-03: 服务器记录玩家关卡最高获得数量

- **触发条件**：玩家成功通关支持带出的关卡。
- **前置限制**：只记录手动挑战，不记录扫荡结果，避免扫荡循环抬高历史记录。
- **操作流程**：
  1. 服务器读取玩家在该 `LevelId` 下已有最高局内金币数。
  2. 使用本次结算经过单次上限裁剪后的有效局内金币参与比较。
  3. 若 `有效局内金币 > 历史最高局内金币数`，更新记录。
  4. 记录更新时间，便于客服与问题追踪。
- **状态变化**：玩家维度新增或更新 `LevelId -> MaxInnerGold` 记录。
- **资源变化**：无直接资源变化。
- **UI 反馈**：关卡详情或扫荡确认界面可展示“历史最高带出基准”。
- **异常边界**：配置关闭后不删除历史记录；再次开启时可继续使用。
- **落地点**：服务器玩家关卡扩展数据、数据库/存档结构、GM 查询。

### R-04: 扫荡时按历史最高记录额外获得金币

- **触发条件**：玩家对支持带出的关卡执行扫荡。
- **前置限制**：
  - 关卡当前配置仍支持局内金币带出。
  - 玩家已通关并满足原扫荡条件。
  - 玩家存在该关卡的历史最高局内金币记录。
- **操作流程**：
  1. 原扫荡逻辑先计算基础扫荡奖励。
  2. 服务器读取玩家该 `LevelId` 的 `MaxInnerGold`。
  3. 计算：`单次扫荡额外金币 = floor(MaxInnerGold * 当前关卡 CarryOutRatio)`。
  4. 多次扫荡时，额外金币按扫荡次数线性累加。
  5. 将额外金币并入扫荡奖励结果。
- **状态变化**：扫荡不更新 `MaxInnerGold`。
- **资源变化**：增加金币，属于关卡重复产出额外来源。
- **UI 反馈**：扫荡预览与扫荡结果中单独显示“历史带出金币”。
- **异常边界**：
  - 无历史记录时额外金币为 0。
  - 倍率调整后，扫荡按当前 `UIlevel.CarryOutRatio` 重新计算。
  - 配置关闭后，历史记录保留，但不参与发奖和展示。
- **落地点**：扫荡服务、奖励预览、扫荡结果 UI、QA 验收。

### R-05: 配置关闭与倍率调整

- **触发条件**：策划修改关卡类型开关或关卡倍率。
- **前置限制**：配置导出与服务器热更/重启规则按现有配置管线执行。
- **操作流程**：
  1. 关闭某关卡类型后，该类型不再发放手动挑战带出金币，也不再发放扫荡额外金币。
  2. 修改某关卡倍率后，后续手动挑战与扫荡都按新倍率计算。
  3. 历史最高局内金币记录默认保留。
- **状态变化**：配置变化不直接改玩家历史记录。
- **资源变化**：影响后续金币产出效率。
- **UI 反馈**：配置关闭后隐藏相关展示。
- **异常边界**：降低 `CarryOutMaxGold` 不反向清理已有历史记录；历史记录只在玩家下次成功手动通关并产生更高有效局内金币时刷新。
- **落地点**：`LevelType.xlsx`、`UIlevel.xlsx`、配置发布流程、版本公告、QA 回归。

## 配置链

### LevelType 类型开关

在 `LevelType.xlsx` 中增加局内金币带出开关，用于控制某一类关卡是否启用本功能。

| 字段 | 类型建议 | 说明 |
|---|---|---|
| `GoldCarryOutEnable` | bool? | 是否启用局内金币带出。空/false 表示关闭，true 表示开启。 |

### UIlevel 关卡参数

在 `UIlevel.xlsx` 中为具体关卡增加局内金币带出参数。

| 字段 | 类型建议 | 说明 |
|---|---|---|
| `CarryOutRatio` | float? | 带出倍率，直接配置小数，例如 `0.5` 表示 50%；空值按 0 处理。 |
| `CarryOutMaxGold` | int? | 单局参与带出计算的最大局内金币数，用于防止过度刷取；空值按 0 处理。 |

### 关联现有配置

| 现有表/逻辑表 | 关联点 | 用途 |
|---|---|---|
| `level.xlsx` | `LevelId`、`Type`、`MopUp` | 判断关卡、扫荡资格、战斗底表。 |
| `UIlevel.xlsx` | `LevelId`、`LevelType`、`CarryOutRatio`、`CarryOutMaxGold` | 配置单关卡带出倍率、单次上限、展示和扫荡预览。 |
| `LevelType.xlsx` | `Id`、`SystemId`、`GoldCarryOutEnable` | 判断玩法类型、入口和是否启用带出。 |
| `Drop` | 不建议复用为动态带出奖励 | 本功能奖励为动态计算，不能用静态 DropId 表达。 |
| `Items.xlsx` | `ItemId = 1` | 发放局外金币货币与展示图标。 |

## 技术方案

### 架构影响

- 服务器结算模块新增“动态局内金币带出”计算分支。
- 扫荡模块新增“基于历史最高记录的额外金币”计算分支。
- 客户端结算页、扫荡预览、扫荡结果页需要支持额外奖励展示。
- 配置导出需支持 `LevelType` 新开关和 `UIlevel` 新字段。

### 数据变更

玩家维度新增关卡历史记录，建议结构：

| 字段 | 说明 |
|---|---|
| `PlayerId` | 玩家 ID。 |
| `LevelId` | 关卡 ID。 |
| `MaxInnerGold` | 手动通关时局内金币获得量最高值。 |
| `UpdatedAt` | 最后刷新时间。 |

可选字段：

| 字段 | 说明 |
|---|---|
| `ConfigVersion` | 记录刷新时配置版本，便于问题追踪。 |

### 接口变更

| 接口场景 | 变更 |
|---|---|
| 战斗结算请求 | 沿用客户端已上报的本局场景拾取金币获得量字段；字段含义和计数口径由客户端与服务端核对。 |
| 战斗结算响应 | 增加额外带出金币奖励明细、是否刷新历史最高。 |
| 关卡详情/扫荡预览 | 返回历史最高局内金币、预计额外金币。 |
| 扫荡响应 | 返回扫荡额外金币明细。 |

## 经济与战斗影响

### 经济影响

- 金币新增了一个与玩家局内表现绑定的重复来源。
- 对金币副本、主线、无限挑战等高频玩法必须谨慎开启。
- 如果支持多次扫荡，额外金币会被扫荡次数放大，需要和体力消耗、每日次数、基础 Drop 奖励一起核算。
- 首期通过 `LevelType.GoldCarryOutEnable` 控制开启范围，并通过 `UIlevel.CarryOutMaxGold` 限制单次额外产出上限。

### 战斗影响

- 若局内金币来自怪物掉落或场景拾取，玩家会更倾向于清怪、绕路、优化拾取路线。
- 不建议让“带出金币”压过通关目标，避免玩家为了金币拖慢关卡节奏。
- 若局内金币和战斗表现强绑定，需要防止异常刷怪、召唤物、重复拾取、复活循环带来的刷量。

## UI 与开放

### 需要展示的玩家信息

| 场景 | 展示内容 |
|---|---|
| 关卡详情 | 该关卡是否支持局内金币带出、当前历史最高基准、预计扫荡额外金币。 |
| 战斗结算 | 本局局内金币、带出倍率、实际额外金币、是否刷新最高记录。 |
| 扫荡预览 | 单次扫荡额外金币、多次扫荡总额外金币。 |
| 扫荡结果 | 基础奖励与历史带出金币分开展示。 |

### 开放规则

- 功能随关卡开放，不单独新增系统入口。
- 未开启的关卡类型不展示相关 UI。
- 开启但玩家无历史记录时，扫荡预览显示额外金币为 0，可提示“手动通关后记录最佳收益”。

## 风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 金币产出膨胀 | 中 | 高 | 配置倍率、单次上限、开启关卡类型白名单；上线前做日收入测算。 |
| 客户端上报被篡改 | 中 | 高 | 服务器按 `CarryOutMaxGold` 做硬上限裁剪，并保留异常上报日志。 |
| 扫荡收益不透明 | 中 | 中 | UI 单独展示历史最高基准与额外金币。 |
| 配置遗漏倍率或上限 | 中 | 中 | `LevelType` 开启但 `UIlevel` 缺少倍率/上限时按 0 处理，并配置检查报错。 |
| 倍率调整引发玩家预期争议 | 低 | 中 | 明确扫荡按当前倍率计算；版本变更时公告或补充说明。 |
| 扫荡反向刷新最高记录 | 低 | 高 | 明确扫荡不更新历史最高，只手动通关可刷新。 |
