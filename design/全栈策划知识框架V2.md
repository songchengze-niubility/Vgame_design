# 全栈策划知识框架 V2

## 目标

将旧数值框架纳入独立于 Vgame 客户端的 `D:/Vgame_design` 项目级策划知识框架，使 `knowledge-base/` 同时承载系统设计、数值规则、Skill 路由、证据与治理；`skills/` 继续作为 Skill 正文唯一来源，`output/` 只保存可重建产物。

## 权威边界

- 正式唯一入口：`knowledge-base/README.md`。
- 数值源文件是迁移证据，不直接成为本仓库正文，也不是新环境重建网页与索引的依赖。
- 权威数值正文保存经原子化的规则、公式、参数、口径、关系和来源摘要。
- 源表、最终配置、报告、备份和 staging 均逐文件登记哈希与处置，但不机械复制。
- 房车采用 C：随机强化 `+30/+60/+100`，权重 `50/30/20`。
- 专武采用 B：保留一个大版本兼容迁移期。

## 全栈数值层

1. 共享底座：术语、属性、定价、概率、统一时间与价值口径。
2. 战斗：战斗属性、公式、强度、难度和战斗验证。
3. 养成：角色、专武、装备、房车及其他成长成本与战斗转化。
4. 经济资源：产出、消耗、库存、价格、Drop 和资源风险。
5. 节奏：开放、主角等级、难度、日程、里程碑和追赶。
6. 商业化与运营：抽卡、通行证、商店、活动和 LiveOps 边界。
7. 验算与配置交付：场景模拟、负向验证、配置映射和发布门禁。

## 原子模型

每个数值原子至少登记：`atomId`、类型、领域、标题、规范化陈述、来源文件与定位、来源哈希、覆盖系统、调用 Skill、证据引用、配置映射、框架节点、状态和验证要求。每个源文件必须在迁移清单中有且仅有一个主要处置。

## 发布规则

先写入 Git 管理的权威源，再在 `output/.staging/` 重建网页、索引、切片、路由清单与图谱。全部自动门禁通过后才替换正式生成物；独立审核前不得把工作流标记为最终验收通过。
