> 文档版本：V1.0（2026-08-12）  
> 交付档位：DOC_ONLY / HIGH

## 1. 设计结论

在招募商店（`Shop.Id=1107`）增加“碎片回收”入口。玩家只能主动回收已经达到**当前配置最高星级**的角色或收容物的同名碎片，并以完整“重复等价包”为单位兑换现有余音货币：

- S/A 品质产出印象余音（ItemId=21）。
- R 角色、B 收容物产出残留余响（ItemId=22）。
- 不足一包的碎片保留；不自动回收；回收不可逆。
- 历史库存上线后立即参与资格计算，但仍由玩家手动处理。
- 最高星级从服务端当前成长配置动态读取，禁止硬编码 6 星。

## 2. 目标与非目标

目标：为满星后的碎片提供稳定、可理解、可审计的消耗口；沿用现有余音经济；避免误回收仍可用于升星的碎片；通过预览、二次确认和事务校验保护玩家资产。

本期不包含：新增货币、独立商店、未满星回收、自动回收、碎片跨角色转换、历史库存自动兑换、SVN 配置/代码实施、UI/Figma 资产。

## 3. 规则冻结

| 规则 ID | 规则 |
|---|---|
| RULE-SR-001 | 入口位于招募商店；功能关闭时隐藏入口并拒绝新请求。 |
| RULE-SR-002 | 仅当前星级达到服务端配置最大星级的对象可回收；上限动态读取。 |
| RULE-SR-003 | 只消耗所选对象对应的同名碎片；服务端通过碎片道具反查对象。 |
| RULE-SR-004 | `可兑换份数=floor(持有碎片/单包碎片数)`，仅兑换完整包，余数保留。 |
| RULE-SR-005 | 玩家手动逐项选择或“全选可回收”，提交前统一预览并二次确认。 |
| RULE-SR-006 | 回收不可逆；批量请求全成或全败，不允许部分成功。 |
| RULE-SR-007 | S/A→21，R角色/B收容物→22；产出沿用 10/3/6 口径。 |
| RULE-SR-008 | 收容物 S/A/B 单包为 100/50/20；角色单包必须回源实际重复转化量，禁止以 60 片代替。 |
| RULE-SR-009 | 历史库存不自动兑换，满足资格和整包条件时进入列表。 |
| RULE-SR-010 | 服务端在同一事务内重新校验资格、库存、配置、开关和幂等性，再扣除与发奖。 |
| RULE-SR-011 | 回收页分角色/收容物，仅显示至少可换 1 包的条目；入口有可回收红点。 |
| RULE-SR-012 | 建议新增客户端+服务端共用逻辑表 `ShardRecycle`；未注册 Luban 前不得称配置就绪。 |
| RULE-SR-013 | 埋点必须覆盖资格库存、预览、提交、结果、消耗、产出、失败原因和配置版本。 |
| RULE-SR-014 | 少发按日志补差；超发先停用并审计，不制造玩家负余额，不回滚已完成兑换。 |
| RULE-SR-015 | 本期不新增货币/独立商店/自动回收，也不允许未满星回收。 |

## 4. 兑换基线

| 对象 | 品质 | 单包碎片 | 单包所得 |
|---|---|---:|---:|
| 角色 | S | 待服务端回源实际重复转化量 | 印象余音×10 |
| 角色 | A | 待服务端回源实际重复转化量 | 印象余音×3 |
| 角色 | R | 待服务端回源实际重复转化量 | 残留余响×6 |
| 收容物 | S | 100 | 印象余音×10 |
| 收容物 | A | 50 | 印象余音×3 |
| 收容物 | B | 20 | 残留余响×6 |

角色升星当前每段消耗 60 片，只能证明升星成本，不能证明抽到重复角色时实际转化多少碎片。角色单包数未回源前，规则文档可以评审，`ShardRecycle` 角色行不得落表或进入联调。

## 5. 玩家流程

1. 玩家进入招募商店，系统根据可回收库存显示入口红点。
2. 进入回收页，在角色/收容物分栏查看至少可兑换一包的条目。
3. 逐项选择份数，或执行“全选可回收”。
4. 页面同步展示每项碎片消耗、余数和 21/22 总所得。
5. 玩家点击回收，弹出不可逆二次确认。
6. 服务端重新校验并原子执行；成功返回实际消耗、奖励汇总和新余额。
7. 若库存、星级、配置或开关变化，整单失败并刷新列表，不发生部分扣除。

## 6. 经济风险

当前招募商店存在 `印象余音×10 → 旅券×1`、`印象余音×10 → 收容凭证×3` 的不限购商品。按本案口径，满星 S 收容物的一个重复等价包可换 10 个印象余音，等价于 1 次角色抽取或 3 次收容物抽取，属于高敏感回抽链。上线前必须用真实卡池概率、成熟账号满星覆盖率、月均重复次数和历史库存完成专项测算；若成熟账号收容物回抽率接近或超过运营护栏，应优先调整招募商店限购/价格或回收产出，不能带风险直接上线。

## 7. 配置与协议建议

建议源表：`Datas\Shop\ShardRecycle.xlsx`，逻辑表 `ShardRecycle`，最小字段为 `Id, FragmentItemId, ObjectType, Quality, BundleCost, RewardItemId, RewardCount, Sort, IsValid`，客户端与服务端同时导出。新表需在 `__tables__.xlsx` 注册，并更新配置表应用归纳与作用关联地图。

批量请求条目：`{fragment_item_id, bundle_count}`。请求需带 `client_request_id` 和 `config_version`；服务端按 `client_request_id` 幂等。响应返回实际消耗、21/22 奖励汇总、剩余碎片、库存版本和错误码。
