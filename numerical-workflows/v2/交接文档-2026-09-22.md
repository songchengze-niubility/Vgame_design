## 1. 这套东西是干什么的（一段话）

`numerical-workflows/v2/` 是 Vgame 数值设计的**自动化生产线**：

设计输入（Git 管理的源表 Excel + 沉淀 Markdown）→ 自动生成 → **43 份 QA 数值交付 Excel**（`framework/04_数值文档/`）→ 再通过"配置粘贴包"流程 → 人工审批后落表到 SVN 正式配置（`${VGAME_CONFIG_DATAS}`）。

它解决的核心问题是：**数值改动的每一步都可追溯、可重建、有门禁**——谁能查到某个数是从哪张源表、哪份 MD、哪条裁决推出来的，改了之后一条命令重新生成全部交付物并自动验算。

## 2. 四条铁律（先背下来再动手）

1. **`04_数值文档/` 是结果，不是输入。** 正式 Excel 每次都从 `01_源表/` + `03_沉淀MD/` 全新重建，禁止从旧交付 Excel 反向拷贝任何参数回来。
2. **SVN 正式配置默认只读。** `formalConfigWriteDefault = DENY`。没有用户对具体批次的明确批准、没有 `VGAME_ALLOW_FORMAL_CONFIG_WRITE=USER_APPROVED` 环境变量，任何工具都不许写 `${VGAME_CONFIG_DATAS}`。Luban 生成物（server_json 等）永远禁止直接改。
3. **源表改动必须先同步 MD，再重跑生产。** 生产门禁 G1 会做"源表 ↔ MD 零差异"检查，直接跑会被拦下来（这是设计如此，不是 bug）。
4. **提交前跑 `scripts/check.ps1`**（仓库总门禁，见 `harness/maintenance-gates.md`）。

## 5. 日常操作

### 5.1 只想看数 / 给 QA 发表

直接用 `framework/04_数值文档/` 里的 Excel，或者用 `QA速查总簿/build_qa_quickbook.py` 重建速查总簿。不需要跑生产。

### 5.2 改了设计（源表 / MD），重新出版

**标准四步**（改源表后必须按此顺序，命令抄自 v2 README）：

```powershell
# 1) 把源表里"源表拥有字段"的改动同步进参数基线 MD
python numerical-workflows/v2/framework/02_AI规则/sync_global_sources_to_md.py --write --report output/numerical-production-workflow-v2/source-md-authority-sync.json
# 2) 刷新知识库参数注册表（knowledge-base/numerical/parameter-registry.json 等）
python scripts/numerical-knowledge/sync_parameter_baselines.py --json-report output/numerical-production-workflow-v2/parameter-baseline-sync.json
# 3) 刷新生产文件清单（哈希变了要登记）
python scripts/numerical-workflows/refresh_manifest.py
# 4) 全量重建 + 验算 + 发布
python scripts/numerical-workflows/run_production.py
```

只改了 MD、没动源表：可以跳过 1~2，但 3~4 建议照跑（成本约几分钟）。

### 5.3 生产运行器实际做了什么

`scripts/numerical-workflows/run_production.py` 七步，任一步失败即整体 FAIL 且**不动已发布的正式文档**：

1. `01-migration-preflight`：迁移前置校验
2. `01b-source-md-consistency`：源表 ↔ MD 零差异（只检查，不偷偷改 staging）
3. 把 `framework/`（排除 04）+ legacy 工作簿复制到 `output/.../runs/<run-id>/` 隔离区，**从零重建**
4. `02-full-generation`：跑 `run_all.py`（G1 源表→MD、G2 MD 参数完整性 + 23 个生成任务）
5. `03-clean-stage`：组装 43 份 QA 交付到 staging
6. `04-dynamic-validation`：独立验算（工作簿数=43、专武兼容物存在、逐项门禁）
7. 发布：目录原子替换进 Git 管理的 `04_数值文档/`，旧版归档到 `output/previous-published/workflow-<run-id>/`；Windows 下若 Excel 被占用会退化为"逐文件替换 + 可回滚"

常用参数：`--run-id <自定义id>`（默认时间戳）；`--no-publish`（只跑 staging + 验算，不更新正式目录，适合试跑）；`--config-root <path>`（指定 Datas 只读来源）。

运行结果看 `output/numerical-production-workflow-v2/latest-production-report.json`：`status=PASS` + `finalWorkbookCount=43` + `dynamicValidationStatus=PASS` 即成功。

## 6. 落表到 SVN 正式配置（谨慎区）

完整规则在 `framework/02_AI规则/配置映射与正式落表流程.md`。链路：

```text
数值结论 → 00_总览/Vgame配置映射总表.xlsx 生成"配置草案"批次
→ 类型/枚举/引用/公式预检（02_AI规则/validate_* 系列）
→ 生成"正式配置粘贴包"（按正式表字段顺序的纯值 + 目标坐标 + 验算）
→ 用户按批次明确批准（状态机 DRAFT→READY_FOR_REVIEW→APPROVED→…→VERIFIED）
→ 备份 + 写入 Datas（此时且仅此时设置 VGAME_ALLOW_FORMAL_CONFIG_WRITE=USER_APPROVED）
→ Luban 导出 + 配置规则检查 + 差异核对 → 回写落地回执；若裁决有变，同步回写 MD
```

`05_验算核算/` 和 `06_最终配置/` 里保存着每个 CHG 批次（CHG008~CHG057 等）的落表前备份、候选备份、校验 json——**排查"当时为什么这么落"时先查这里，再查对应 MD**。

## 10. 常见坑（前任踩过的）

- **源表改完直接跑生产被 G1 拦下**：不是坏了，是"零差异"设计；先跑 `sync_global_sources_to_md.py --write`（§5.2 第 1 步）。
- **发布时 Excel 被 WPS/Excel 占用**：运行器自动退化为逐文件替换并留完整归档，可回滚；但最好发布前关掉所有打开的交付表。
- **Windows 换行毁哈希**：manifest 对文本用 UTF-8/LF 归一化哈希、Excel 用原始字节 SHA-256，别手动"格式化"文本文件。
- **专武源页已删除**：B 裁决要求兼容期，专武终稿从冻结的参数 MD 继续生成，不要试图恢复源页或把旧消耗自动迁到收容物。
- **节奏公式缓存缺失**：按裁决保留已确认 MD 值，不用空值覆盖历史结论。
- **想改正式配置走捷径**：没有。粘贴包 + 批次审批 + 环境变量三重锁是故意的，绕过等于丢掉全部可追溯性。
