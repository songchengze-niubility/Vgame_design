# 映射装备评分公式沉淀（2026-09-09）

> 配套提案：`proposals/映射装备评分公式修正-2026-09-09.md`（PROP-20260909-EEQUIP-SCORE）。
> 本文是该提案的数值侧沉淀：最终口径、单价表、裁决过程与回归结论。

## 1. 最终评分口径

```text
装备评分 = round( Σ主属性(最终主属性值 × UnitPrice)
                + Σ数值词条(词条数值 × UnitPrice)
                + Σ技能词条( Effect表Score，直读 ) )
```

- **计算方**：服务端；经 `proto.cmsg.SEEquipment.score`（int）与
  `SEEffectAttr.score`（double）下发。客户端零计算，只透传
  （`MappingEquipSystem.lua:184`），用于一键穿戴/红点
  （`MappingEquipSystem.lua:1597`：等级/品质/评分任一更高即推荐）。
- **旧公式废弃**：`评分 = 20×等级上限×品质系数 + 1.25×Σ词条评分`
  （globals_conf `SpecialEquipmentScoreA=20/B=1.25`，两字段退役）。
- **废弃原因（实测）**：等级不参与评分、词条分与 roll 值脱钩、主属性不计分、
  品质双重计入；出现"属性全面更高的装备评分反而更低"（蓝千湖项链 Lv25=494
  < 蓝旅行者项链 Lv15=632）。

## 2. 评分单价表（SpecialEquipmentScorePrice.xlsx，唯一新增配置）

| 属性 | UnitPrice | 锚点与说明 |
|---|---|---|
| Attack（平面） | 1.0 /点 | 基准：1 点攻 = 1 分 |
| Armor（平面） | 1.5 /点 | 定价表：10 点防 = 1% 攻 |
| Hp（平面） | 0.3 /点 | 定价表：50 点血 = 1% 攻 |
| AttackBonus / ArmorBonus / HpBonus | 7.5 /1% | 定价表 15 × **0.5 平衡系数**（见 §4-3） |
| CritLevel / EnergyPreAddBonusLevel | 0.166667 /点 | 定价表：90 点 = 1% 攻 |
| CritDmgBonusLevel | 0.136364 /点 | 定价表：110 点 = 1% 攻 |
| CoolDownReduceLevel | 0.115385 /点 | 定价表：130 点 = 1% 攻 |

- 表内已落镜像：`06_最终配置/映射装备/SpecialEquipmentScorePrice.xlsx`。
- 主属性与词条按"属性"同价（同属性主/副同价）；百分比按"每 1%"计价。
- 技能类词条（3 万段 ID）不换算，直读 `SpecialEquipmentEffect.xlsx#Score`
  （当前统一 150）。
- 品质不单独计分：品质经主属性 GradeCoefficient（0.2/0.3/0.45/0.7/1）自然进入。

## 3. 主属性口径（不变，引用）

```text
程序主属性原值 = Value × Grow^(装备等级/5) + Param
最终主属性     = 程序原值 × GradeCoefficient
Value=T×0.6238763, Grow=1.0830838, Param=T×(-0.6257103)，T=60级红装目标值
设计目标：等级倍率 = 0.05 + 0.95×((等级-5)/55)^1.35（凸曲线）
```

## 4. 关键裁决记录（2026-09-09，与数值策划对话定稿）

1. **评分定位 = 属性总量排序器**（定位 A）：一键穿戴/红点语义已绑定"评分高=更好"。
2. **单价锚点 = 共享参数基线「属性定价」表**，而非 Effect 表 Score÷ValueMax 派生。
   初版曾用派生法播种，交叉验证发现与定价表冲突（等级类差 15~20 倍、
   百分比差 2 倍+），且实战对照（旅行者腰带 vs 千湖礼仪腰带，见 §5）支持
   定价表口径，遂整体改锚。
3. **百分比单价 ×0.5**（15→7.5）：词条投放决定维持旧表不动（CHG027 搁置），
   旧投放下等级类词条低中等级段相对 %词条偏差中位 1.92×，%减半使中位档
   竞争回归中性。已知取舍：低等级段一键穿戴对 %词条偏保守。
   **投放修正落地时须恢复 % 单价至 15。**
4. **Effect 表 Score 职责收窄**：不再参与属性词条计分，仅作技能词条直读来源。
5. **全局缩放系数 K 不设**：评分即属性分取整（用户明确去掉 1.77）。

## 6. 词条投放的已查实问题（本次未修，CHG027 搁置）

用定价表反查 `SpecialEquipmentEffect.xlsx` 红档 ValueMax：

1. **等级类（暴伤/暴击/能量/冷却）双曲线只在档顶满足定价**：每品质段内
   `暴伤VM ÷ (攻击%VM×100)` 从档首 7.33 线性收敛到档顶 110；档首等级类
   投放量仅为定价等价值的 1/15。根因：等级类是一条跨 60 档的连续凸曲线，
   %词条是品质内近线性曲线，两族只在品质段顶相交。
2. **平面词条恒为非平面的 7.5 倍当量**（172.7% vs 23.03% 攻）：投放按
   "实际属性量 = 23.03%×主攻击面板 11250"对齐（终盘面板口径），与定价表的
   标准人面板口径（1%攻=15点攻）混用。
3. 处理：本次评分不动投放，以 %×0.5 平衡；CHG027 对齐候选表及脚本已存档
   （`06_最终配置/映射装备/CHG027_搁置_*.py`，含 240 行等价化方案与四项
   验算，验算全绿），后续启动投放修正时可直接复用。
