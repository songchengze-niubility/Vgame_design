## 当前权威结论

- `角色星盘 = 角色能效`。
- 当前设计共有 `19` 个唯一节点、`51` 次激活/升级。
- 开放等级仅使用 `Lv1 / Lv20 / Lv30 / Lv40 / Lv50 / Lv60`，取消 `Lv10` 能效门槛；各阶段新增点数为 `7 / 6 / 12 / 13 / 7 / 6`。
- 初始技能在前期激活，但技能升级后置：Lv20只允许被动1与普攻升到Lv2，不允许任何技能在Lv20点满；首个技能满级出现在Lv40，其余满级分布到Lv50与Lv60。
- 属性投放由 `4` 个基础属性节点和 `6` 个二级属性节点组成，共 `10` 个属性节点、`32` 次属性激活/升级。
- `4` 个基础属性节点共 `14` 次升级：两个单属性节点各4级、两个双属性节点各3级。
- `6` 个二级属性节点共 `18` 次升级：每个节点3级。
- 二级属性继续按每个角色的 A/B/C 三种偏向配置；每种偏向对应两个节点。
- 能效属性升级采用“替换配置”而非数值叠加：同一节点每升一级都必须读取一个更高的累计属性配置。
- `AttrKey` 当前使用 `1~32`。Lv1保留原 `1~10`；Lv2使用 `11~20`；Lv3使用 `21~30`；两个4级基础节点的Lv4使用 `31~32`。
- 当前二级属性总偏向预算为 `1.8`；按18次升级折算，每级投放 `0.1`，A/B/C 各承担 `0.6`。
- 星盘需要重新纳入基础生命、基础攻击和基础防御投放。旧“星盘不投放基础属性”的口径自本次确认起废弃。
- 4个基础属性节点的结构、开放等级和标准人基准已经确认：标准人满级合计基础生命 `+6000`、基础攻击 `+1800`、基础防御 `+1200`，折合 `1.2` 个标准人基础属性。
- 每个角色的基础属性节点必须按 `养成属性分配.xlsx/角色属性分配` 的 `最终生命比 / 最终攻击比 / 最终防御比` 分别偏移；这三个最终比例已经包含职业比例、角色微调和品质系数，不再让所有角色使用同一套固定基础属性。
- 最终配置已按当前点位拓扑落地为 `Node1~19`；真实 SVN 配置仍保持只读，尚未同步。

布局与连线口径：第一排新增 `Node18、Node19`，分别位于普攻和必杀之前；第二排新增 `Node4、Node5`，分别位于两条A属性支路之前。基础属性相关链路为 `1→18→10`、`1→19→11`、`2→4→16→12`、`2→5→17→13`。

逐角色计算口径：

- 满级生命 = `ROUND(6000 × 最终生命比)`；满级攻击 = `ROUND(1800 × 最终攻击比)`；满级防御 = `ROUND(1200 × 最终防御比)`。
- 生命和攻击各拆成两半：4级单属性节点取四舍五入后的一半，3级双属性节点承担余量；防御在两个3级双属性节点间按同样方式拆分。
- 每条支路按等级数等比分段并四舍五入为整数，末级精确等于该支路满级值；两条支路相加必须精确回收到角色满级目标。
- 配置仍采用累计替换：升级读取新的累计值，不叠加低级行。

### 替换型AttrKey规则

- Map每一级直接填写该级对应的累计 `AttrKey`；客户端读取当前节点等级对应行，不把低级配置再次相加。
- 二级属性配置由Lv1基准值按 `1倍 / 2倍 / 3倍` 生成，例如攻击百分比 `0.075 / 0.15 / 0.225`、暴击等级 `675 / 1350 / 2025`、技能冷却等级 `975 / 1950 / 2925`。
- 每角色 `EnergyEfficiencyAttrList` 按AttrKey顺序登记32个ID。全部属性ID统一使用 `HeroId×100+AttrKey` 的六位编号，例如角色1001对应 `100101~100132`。
- `HeroEnergyEfficiencyAttr.xlsx` 当前为31组角色×32项，共992条；测试角色1000仍保留8项占位配置。
