# 映射装备养成属性数值沉淀

## 沉淀范围

本文只沉淀映射装备在养成侧、属性侧的数值口径，并且是该范围内的唯一权威口径。源表、设计稿、生成报告与配置只能作为回源证据或落地结果；任何变更只有经用户确认并写入本文后，才成为当前有效规则。完整配置字段映射、生成顺序、ID 规则与落表门禁见 `映射装备配置落地方式-2026-07-13.md`。

包含：

- 映射装备等级与品质。
- 主属性/副属性品质系数。
- 部位固定主属性。
- 主属性等级曲线与 60 级红装目标值。
- 副属性等级曲线与 60 级红装单条目标值。
- 副属性词条池沿用边界。
- 旧框架 `主属性1 / 主属性2` 结构的废弃边界。

不包含：

- 映射装备副本产出、宝箱概率、首通奖励、钥匙来源。
- 合成、制作、分解、材料、金币、洗练消耗。
- ItemId、DropId、UIlevel、正式配置承接。
- 全局金币经济、毕业周期和产销验算。

以上内容后续放入经济框架或对应玩法/配置模块内沉淀。

## 核心结论

- 映射装备强度由 `装备等级 + 装备品质 + 部位主属性 + 副属性` 共同决定。
- 新口径下每个部位只有 1 条固定主属性，不再使用旧框架的 `主属性1 / 主属性2` 双主属性结构。
- 旧 `映射装备_框架生成.xlsx` 中的 `主属性2` 翻倍差异，属于旧框架迁移风险，不作为新映射装备属性口径的阻塞项。
- 攻击仍按单一 `攻击` 属性处理，不拆物理攻击和魔法攻击。
- 映射装备副属性池不再投放 `物理伤害加成`、`魔法伤害加成`。
- 主属性不再投放攻击、生命、防御百分比；武器和六个防具部位只投放基础数值，装置与饰品保留等级属性。
- 红色装备不再拥有每件装备固定的专属效果或固定普通词条组合；红装固定4条副属性，全部从10类普通副属性池中无放回随机。

## 品质系数

| 品质 | 主属性品质系数 | 副属性品质系数 |
|---|---:|---:|
| 绿 | 0.20 | 0.35 |
| 蓝 | 0.30 | 0.50 |

| 金 | 0.70 | 0.85 |
| 红 | 1.00 | 1.00 |

设计口径：

- 主属性品质系数不变；副属性品质系数独立成长。
- 副属性绿/蓝/紫/金/红为 `0.35 / 0.50 / 0.65 / 0.85 / 1.00`，低品质之间保持稳定递增。
- 红装为基准 `1.00`。
- 红装随机上限倍率为 `1.40`，绿色定值倍率为 `1.00`，因此同等级同词条的红色上限/绿色定值为 `1.00×1.40/(0.35×1.00)=4.00`。

## 主属性曲线

设计目标公式（用于确定等级倍率目标）：

```text
主属性 = 60级红装主属性目标值 * 主属性品质系数 * 主属性等级倍率
```

```text
主属性等级倍率 = 0.05 + 0.95 * ((x - 5) / 55)^1.35
x = 装备等级
```

`SpecialEquipmentMain` 程序执行公式：

```text
程序主属性原值 = Value * Grow^(x/5) + Param
最终主属性 = 程序主属性原值 * 主属性品质系数
x = 装备等级
```

现有程序指数式与设计目标的 1.35 次幂式不是同一函数族，因此配置转换采用以下固定规则：

- Lv5 等级倍率必须精确等于 `0.05`。
- Lv60 等级倍率必须精确等于 `1.00`，保证下表 60 级红装目标值不漂移。
- 在满足两个端点的前提下，对 Lv10～Lv55 的完整精度目标倍率做最小二乘拟合。
- 公共参数：`A=0.6238763354456975`、`B=1.083083786770521`、`C=-0.6257103438710419`。
- 对任意一条主属性，设其 60 级红装目标值为 `T`：

```text
Value = T * A
Grow  = B
Param = T * C
```

本次拟合的等级倍率均方根误差为 `0.0127588083`，最大绝对误差为 `0.0218338131`（Lv15）；Lv5 与 Lv60 误差均为 `0`。该转换规则是 Main 配置参数的唯一落表口径，不得再使用三锚点或展示层三位小数反推。

Main 配置粒度沿用正式表既有方法：当前480件装备引用171个在用 `Attribute1List` Main ID；`SpecialEquipmentMain` 完整保留190条兼容定义。相同ID只保留一条配置，同部位使用相同属性类型与曲线参数，不得进一步合并为8条共享ID。旧 `Attribute2List` 清空。

## 副属性曲线

副属性标准值以 2026-08-14 已确认的当前单条上限为回源基准：

```text
新标准值 S = 当前 ValueMax × 50%
副属性实际值 = S × 属性类别等级倍率 × 副属性品质系数 × 品质随机倍率
```

百分比属性（`AttackBonus / HpBonus / ArmorBonus`）采用前期高、成长慢的曲线：

```text
百分比等级倍率 = 0.45 + 0.55 * ((x - 5) / 55)
x = 装备等级
```

固定值/等级属性（`Attack / Armor / Hp / CritLevel / CritDmgBonusLevel / EnergyPreAddBonusLevel / CoolDownReduceLevel`）采用前期低、成长快的曲线：

```text
固定值等级倍率 = 0.03 + 0.97 * ((x - 5) / 55)^1.35
x = 装备等级
```

现有 `SpecialEquipmentSubAttrCoef` 只有一列公共倍率，无法直接表达两条曲线。最终配置采用纯配置兼容方案：

- 按当前正式480件装备覆盖的60组“5品质×12等级”建立独立副属性池。
- 百分比/固定值等级倍率与副属性品质系数一并预乘进 `SpecialEquipmentEffect.ValueMin / ValueMax`，Effect直接存玩家最终获得的副属性区间。
- `SpecialEquipmentSubAttrCoef.SubAttrCoef` 的12档统一写 `1.00`，避免重复缩放。
- `SpecialEquipmentQuality.QualityCoefficient` 保留作词条参数门槛/评分；副属性取值时不得再次乘该系数。
- 新池使用 `EffectDrop.Id=5001～5060`；全部新装备模板改指向对应品质等级池。
- 新增普通副属性定义使用 `Effect.Id=50001～50600`，旧定义与旧池保留以兼容历史数据，但不再被新装备模板引用。

## 副属性随机边界

- 副属性生成条数以本节为准。
- 副属性词条池和生成权重除已明确删除项外沿用旧配置。
- 单条副属性不因条数增加而摊薄。
- 绿/蓝/紫只随机副属性类型，生成后的数值固定；金/红同时随机类型和数值。
- 金装数值区间为标准值的100%～120%，红装为120%～140%。
- 副属性池共 10 类，已删除 `物理伤害加成`、`魔法伤害加成`。
- 副属性不允许重复词条；洗练后也不允许出现重复词条。
- 红装取消专属效果；原每件红装的专属效果定义允许为兼容旧ID保留，但任何在用红装词条池都不得引用。
- 红装按等级引用12个红色品质等级池，每件红装从对应十类普通副属性中无放回随机4条；旧红装专属池ID保留但退出新装备引用。
- 洗练消耗、装备高级材料、分解来源、金币成本不在本文展开，进入经济框架。

## 合成投入等级区间

- `PortableRange` 使用8个区间，对应 `PortableEquipCompound.RangeId=1~8`。
- 可投入最低等级规则：`EquipMinLv = max(1, LevelMin - 5)`。
- 可合成等级区间：`1~15、5~20、10~25、15~30、20~35、25~40、30~45、35~50`。
- 对应可投入最低等级：`1、1、5、10、15、20、25、30`。
