# 映射装备配置落地方式

> 日期：2026-07-13  
> 作用：记录映射装备从沉淀 MD 到最终配置镜像、再到正式 Vgame 配置表的完整方法。  
> 边界：本文记录配置职责、字段映射、ID、生成顺序和验证方法，不替代属性、掉落、经济数值沉淀。

本文是映射装备模块专项规则；批次审批、正式 Datas 写入授权、备份、Luban 导出与回执仍继承 `02_AI规则/配置映射与正式落表流程.md`。

## 1. 总原则

1. 数值权威源是 `03_沉淀MD`，不再依赖旧参数表或历史数值 Excel。
2. `${VGAME_CONFIG_DATAS}` 下的正式 Excel 只提供正式 Schema、现有 ID、现有装备模板和引用事实；未经用户确认不得由生成器修改。
3. `04_数值文档` 和 `06_最终配置` 都是生成物，不作为数值反向来源。
4. 所有数值修改先改对应沉淀 MD，再运行生成器；禁止只手改最终 Excel。
5. ItemId、DropId、GenerateId 都是跨表外键。改号必须按名称或业务键迁移全链引用，不能只改主表。
6. 用户确认最终镜像后，才进入正式配置表；正式配置落地仍需备份、导表和项目校验。

出现冲突时按以下顺序处理：

1. 用户当前明确确认的规则。
2. 对应业务沉淀 MD。

4. 生成器和最终配置镜像。
5. 旧数值文档、旧正式配置观察。

生成物不得反向覆盖前两级。

## 4. 当前正式 ID 规则

### 4.1 打造主材

- 正式 ItemId：`1080-1151`，共 72 个。
- 组合：8 打造档 × 3 大类 × 3 品质。
- 打造档顺序：`10 / 20 / 30 / 40 / 45 / 50 / 55 / 60`。
- 大类顺序：`武器 / 防具 / 首饰`。
- 品质顺序：`紫 / 金 / 红`。

公式：

```text
ItemId = 1080 + 打造档索引 * 9 + 大类索引 * 3 + 品质索引
```

索引均从 0 开始。正式改号时必须以 `Items.Name` 为业务键重新映射，不得只按旧 ID 偏移推算。

### 4.2 打造副材

| 名称 | ItemId |
|---|---:|
| 映射装备副材1 | 1152 |
| 映射装备副材2 | 1153 |
| 映射装备副材3 | 1154 |
| 映射装备副材4 | 1155 |

消耗关系：

| 装备大类/部位 | 副材 |
|---|---|
| 武器 | 1152 + 1153 |
| 防具：头部、护甲、手套、腰带、鞋子 | 1153 + 1154 |
| 首饰：装置、饰品 | 1154 + 1155 |

### 4.3 层级宝箱

- 正式 ItemId：`4201-4350`，共 150 个。
- 组合：30 层 × 5 品质。
- 品质顺序：`绿 / 蓝 / 紫 / 金 / 红`。

公式：

```text
ItemId = 4201 + (层数 - 1) * 5 + 品质索引
```

宝箱的 `Items.ParaList` 一对一引用相同 ID 的 `SpecialEquipmentGenerate.Id`。

### 4.4 UI预览占位道具

- 正式 ItemId：`4351-4402`，共 52 个UI展示占位道具。
- 等级箱占位：`4351-4354` 对应 5/10/15/20 级，`4365-4372` 对应 25/30/35/40/45/50/55/60 级；统一使用通用映射装备箱图，不区分真实宝箱品质。
- `4355-4363`：随机主材，分别承载实际会用到的 9 组“打造档位 × 最高可掉品质”展示。
- `4364`：随机映射装备副材，只表示四种副材随机，不对应任何具体副材。
- `4373-4402`：第1～30层逐层独立的首通宝箱展示道具，ID与层数一一对应；图标和展示品质匹配本层固定首通箱，描述写明该层可能开出的装备等级。
- 这些道具只允许出现在 `UIlevel.Reward / FirstReward` 的展示字段；禁止进入 Drop、背包、商店、宝箱开启或打造消耗。
- 图标口径：12 个常规等级箱只表达装备等级；30个首通箱使用对应固定品质的 `item_specialequipment_1.png` 至 `item_specialequipment_5.png`；随机主材使用 `item_mappingequip_random_mainmaterial.png`，随机副材使用 `item_mappingequip_random_submaterial.png`。

## 6. 属性配置方式

### 6.1 SpecialEquipment

1. 以正式 `SpecialEquipment.xlsx` 的 190 件装备为底稿。
2. 保留正式装备 ID、名称、部位、品质、效果池等非目标字段。
3. 每件装备保留自己原有的 `Attribute1List` 独立 Main ID。
4. `Attribute2List` 清空，当前版本每件装备只有一个主属性。
5. 禁止把全部装备指向同一个 Main ID。

### 6.2 主属性

程序公式：

```text
主属性 = Value(a) * Grow(b) ^ (装备等级 / 5) + Param(c)
```

配置规则：

1. `SpecialEquipmentMain` 每件装备单独一行，沿用该装备正式 `Attribute1List` 的 Main ID。
2. 属性类型由部位决定：武器攻击、头盔生命、护甲生命、手套防御、腰带防御、鞋子防御、装置暴击伤害等级、饰品暴击等级。
3. 品质差异由 `SpecialEquipmentQuality.GradeCoefficient` 额外相乘。
4. 190条 Main 记录均使用沉淀MD已确认的公共拟合参数：`A=0.6238763354456975`、`B=1.083083786770521`、`C=-0.6257103438710419`；对目标值 `T` 写入 `Value=T×A / Grow=B / Param=T×C`。
5. 该拟合已确认允许 `Param` 为负数；必须校验 Lv5 与 Lv60 精确命中，并校验中间档误差不超过沉淀MD记录的误差边界，不得再用旧三锚点或展示层取整值反推。

### 6.3 副属性

1. `SpecialEquipmentEffect` 保持 `ValueMin～ValueMax` 数值随机，普通副属性的 `ValueMax / ValueMin / RandomMin` 按沉淀MD的60级红装十类目标区间重写；不得改成 `ValueMin = ValueMax`。
2. 正式表现有4组普通副属性ID（`1～12 / 101～112 / 201～212 / 301～312`）继续保留ID兼容，但数值基准统一写为60级红装单条区间；品质差异由 `SpecialEquipmentQuality.QualityCoefficient` 额外相乘。
3. 等级差异由 `SpecialEquipmentSubAttrCoef.SubAttrCoef` 额外相乘，12档为 Lv5～Lv60；不把逐等级完整曲线展开写入 `SpecialEquipmentEffect`。
4. `SpecialEquipmentEffectDrop` 保留正式池ID；所有在用池必须移除物理/魔法伤害引用并按 `Attribute` 语义去重。通用品质池 `101 / 201 / 301` 各保留10类普通词条；37件红装继续引用既有池ID `1～37`，但各池内容统一改成红装10类普通词条等权候选，不再引用任何专属效果。
5. 同一件装备的副属性语义不得重复，初始生成和洗练后均按该规则验证。
6. 物理伤害加成、魔法伤害加成的历史效果定义行可保留，但不得再被任何在用映射装备词条池引用。
7. 红装 `EffectNumMin=EffectNumMax=4`，从对应十类普通词条池无放回随机4条；原专属效果定义行可保留以兼容旧ID，但必须保持零在用引用。

### 6.4 品质系数原子更新

`SpecialEquipmentQuality` 不能单独落表，必须与以下内容同一批评审：

- `SpecialEquipment`
- `SpecialEquipmentMain`
- `SpecialEquipmentEffect`
- `SpecialEquipmentEffectDrop`

否则可能发生旧 Main 已预乘品质、又被 `GradeCoefficient` 二次乘算的问题。

## 7. 合成和打造配置方式

### 7.1 合成

1. `PortableRange` 配 8 档，`LevelMin~LevelMax` 就是该档合成结果等级范围：`10~10 / 15~20 / 25~30 / 35~40 / 40~45 / 45~50 / 50~55 / 55~60`。
2. 可投入最低等级固定为：`EquipMinLv = LevelMin - 5`，对应为：`5 / 10 / 20 / 30 / 35 / 40 / 45 / 50`；不做额外下限钳制。
3. `UnlockId` 是 `unlock/Unlock.xlsx.Id` 外键，不直接填装备等级；映射装备不可复用旧条件，必须新增 8 条本模块专用条件。使用正式表连续空闲 ID `1190~1197`，分别要求玩家等级 `10 / 15 / 25 / 35 / 40 / 45 / 50 / 55`。
4. `PortableRange.RangeId 1~8` 分别对应 `SpecialEquipmentGenerate 4401~4408` 的合成结果等级池。
5. `PortableEquipCompound` 配 8 档 × 5 投入品质，共 40 行，必须与 `PortableRange` 原子更新。
5. `EquipResult` 引用 `4401-4408`，等级概率只在 `SpecialEquipmentGenerate.GradeList` 配置。
6. 成品品质概率只在 `PortableCompoundProb.QualityList` 配置，权重和固定为 1000。
7. `PortableEquipCompound` 只配置档位、投入品质、结果引用和金币，不重复配置成品品质概率。

### 7.2 打造

1. 打造与合成的开放链分离：合成口径不变；打造使用 `SystemOpen.Id=54 -> UnlockId=1198 -> UnLock_UUT_Level(250061)`，通关映射装备第6层后开启。
2. `PortableEquipCraft` 保留 360 行：8 部位 × 3 主材品质 × 15 个既有档内引用位；不以多行实现等级选择。
3. `EquipResult` 引用 `4501-4620`。玩家只选择主材档位；同一打造档的 Generate 均配置相同的等级概率池，部位仍由 Generate 固定。
4. `MainCost` 为一个正式主材 ItemId，数量固定为 1。
5. `AssistCost` 为对应两种副材和数量。
6. `Gold` 使用对应打造档金币。
7. 成品品质概率只在 `PortableCraftProb.QualityList` 配置，不能重复写入 Generate 或 Craft 表。
8. `PortableCraftProb` 共 180 行：60 锻造台等级 × 3 主材品质，权重和固定为 1000。

## 8. 副本掉落和 UI 配置方式

### 8.1 Drop_dungeon

逻辑结构：

```text
常规一级入口 DropId
  -> 固定宝箱池
  -> 额外宝箱池
  -> 第6层起：主材池
  -> 第6层起：副材共用池
```

首通另使用 `20000010-20000039`，常规入口使用 `20005101-20005130`。

当前二级池：

| DropId | 用途 |
|---|---|
| `22101-22130` | 每层固定宝箱池 |
| `22201-22230` | 每层额外宝箱池，包含未触发项 |
| `22301-22305` | 保留不用；第1～5层不生成主材池 |
| `22306-22330` | 第6～30层主材池，包含未命中项 |
| `22400` | 4 种副材等权共用池 |
| `22451-22453` | 已由 `CHG-013` 退役；不再存在有效随机池行。原6行中2102～2106复用为第7/11/16/21/26层固定首通箱，2107标记`##`停用。 |

正式 `Drop_dungeon.xlsx` 的 `ID / DropId / DropId2` 存在公式和相对引用风险：

1. 最终镜像按稳定规则排序：8 位一级 DropId 在前并升序，5 位二级池在后并升序；同一 DropId 的多行保持原生成顺序且必须连续。
2. 主体排序仍为首通一级包 `20000010-20000039`、常规一级包 `20005101-20005130`、二级池 `22101-22400`。`CHG-013` 因禁止插行，复用原22451～22453所在的2102～2106行承载第7/11/16/21/26层固定首通箱；这5行属于已确认的非连续物理行例外，逻辑 DropId 仍归入对应首通包。
3. `22101-22130` 固定箱池始终保留每层绿/蓝/紫/金/红5行；品质尚未开放时对应 `DropWeight=0`，避免因概率门槛调整而插删公式行。
4. `22201-22230` 额外箱池在额外概率大于0时同样保留5个品质行；未开放品质写0权重，未触发额外箱继续使用空掉落权重。
5. 最终镜像中公式列留空。
6. 禁止脚本直接覆盖正式公式单元格。
7. 禁止对正式表执行 `insert_rows/delete_rows`。
8. 新增行时由人工在 Excel/WPS 中插入、复制相邻公式并下拉，再粘贴第 7 列起的纯数据字段。
9. `DropItem_id` 改号必须同步 Items、UI 预览和打造消耗。
