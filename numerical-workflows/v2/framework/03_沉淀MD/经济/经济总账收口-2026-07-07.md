## 关卡型奖励沉淀硬口径

所有关卡型模块都必须按“最小可领取单位”沉淀奖励投放。只记录 DropId、RewardId、预览字段或模块汇总，不算完成沉淀。

关卡型模块包括但不限于：主线、困难主线、资源副本、旅券副本、映射装备副本、BOSS挑战、无限挑战、竞技场（PVPVE）、爬塔、大秘境，以及后续所有以 LevelId、层数、难度层、战斗节点、赛季关卡为奖励单位的玩法。

每个关卡/层级/节点至少要沉淀以下字段：

| 字段 | 要求 |
|---|---|
| 关卡定位 | 玩法、LevelType、LevelId/层数/节点ID、章节/难度/赛季归属。 |
| 消耗与次数 | 体力/门票/挑战次数/扫荡次数/多倍结算次数；没有则显式写无。 |
| 首通/一次性奖励 | 首通、三星、首次达成、最佳成绩、章节星级等一次性投放，需要展开真实 Drop 内容。 |
| 常规/重复奖励 | 通关、扫荡、结算、保底、基础掉落等可重复投放，需要展开真实 Drop 内容。 |
| 概率/权重 | DropType、DropWeight、数量上下限、随机包层级；如只有固定奖励，也要写固定口径。 |
| 周期奖励 | 日/周/赛季/活动刷新、排行结算、周期重置奖励；没有周期奖励时显式写 `无/未观察`。 |
| 展示与真实包差异 | UI 预览字段和真实 Drop 包分开记录；预览不能替代真实奖励。 |

验收标准：关卡型模块的 MD 和模块产销表中，不能只留下 `待 DropId 展开` 作为最终状态；若正式配置已有奖励包，必须逐关展开到道具、数量、概率/权重、周期口径。
