# 模块读写规则

## 通用顺序

1. 读 `00_总览`。
2. 读 `01_源表` 中相关全局底座。
3. 读用户给出的策划案、历史文档或需求补充。
4. 列数值点和影响范围，先和用户确认修改思路。
5. 更新 `03_沉淀MD` 的参数 ID、公式、状态、来源和变更记录。
6. 依据源表与 MD 刷新本次生成物，创建不读取旧 `04` 的全新 staging。
7. 生成 `05_验算核算`，检查 MD → 终稿映射、文件集合、公式与终稿独立性；通过后整体发布并复验。

## 模块入口

| 模块 | 优先源表 | 主要产物 |
|---|---|---|
| 养成 | 属性定价、养成属性分配、术语表 | 单系统养成数值文档、养成验算核算 |
| 经济 | 道具定价、经济口径、术语表、养成属性分配（仅涉及养成预算时） | 产销文档、经济验算核算 |
| 节奏 | 节奏口径、术语表 | 开放节奏文档、节奏验算核算 |
| 战斗 | 战斗属性、战斗公式、属性定价、节奏口径 | 战斗模型文档、战力核算 |

## 养成属性比例读写

- 角色属性比例优先读取 `01_源表/养成属性分配.xlsx` 的 `角色属性分配` 页签。
- 专武属性比例优先读取 `01_源表/养成属性分配.xlsx` 的 `专武属性分配` 页签。
- 角色与专武属性比例统一使用生命、攻击、防御三主属性；攻击为单一攻击属性，不再拆分物理攻击和魔法攻击。
- 所有模块读取历史配置时，`PhysicsAttack`/`MagicAttack` 合并为 `攻击`，`PhysicsAttackBonus`/`MagicAttackBonus` 合并为 `攻击百分比`；若统一字段 `Attack`/`AttackBonus` 与历史字段同时存在，沉淀口径不得重复叠加。随机池合并时权重不累加，同类随机池内各属性保持同权。
- `03_沉淀MD/参数基线/养成参数基线.md`、正式交付表或生成报告中的角色/专武系数，必须能回到 `养成/<Sheet>!<Cell>`；旧 `养成/参数.xlsx` 已删除。

## 奖励与概率处理

- 不设独立的一级 `奖励概率` 数值模块预先定义全部玩法产出。
- 玩法产出、消耗、掉落、概率、奖励包在对应玩法/系统模块内设计。
- 经济总账只在后置阶段汇总、对比和异常校验。
- DropId/RewardId 随机包展开、UIlevel 奖励预览一致性属于配置链校验，不替代具体模块的产出定义。

## 禁止事项

- 不把单系统最终展开表当源表。
- 不把生成结果反写进源表，除非用户明确确认这是新的全局口径。
- 不在源表中隐藏临时假设。
- 不从 `_shared/共享参数.xlsx` 或四模块 `参数.xlsx` 直接决定终稿。
- 不允许最终文档出现无法回到 MD 参数 ID 或系统沉淀章节的关键硬编码。
- 不用 `run_all.py` 的生成结果无提示覆盖 `04_数值文档`。
- 不直接手改 `04_数值文档` 形成新参数；变更必须回到所属源表或 MD 后重建。
