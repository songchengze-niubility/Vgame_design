# 配置映射与正式落表流程

> 本流程在数值设计与 Vgame 正式配置之间增加“配置草案”和“正式配置粘贴包”两层。草案负责追踪与评审，粘贴包负责按正式字段顺序交付纯值；两者都不是新的参数源，也不是运行时配置源。

## 权威边界

| 层级 | 权威内容 | 是否允许直接作为正式配置写入依据 |
|---|---|---|
| `01_源表` | 全局事实、术语、定价、战斗公式与公共口径 | 是，但必须与系统 MD 一起形成可追踪结论 |
| `03_沉淀MD` | 单系统参数、公式、设计裁决与稳定参数 ID | 是，数值决策的设计权威 |
| `04_数值文档` | 从源表与 MD 派生的数值交付和阅读结果 | 否，不得反向成为第二参数源 |
| `00_总览/Vgame配置映射总表.xlsx` | Vgame Schema 镜像、配置草案、审批记录和落地回执 | 仅作为待审批变更载体；审批前不得写正式配置 |
| `04_数值文档/配置粘贴包/*.xlsx` | 按正式表字段顺序排列的纯值复制区、目标坐标和验算 | 可作为人工粘贴载体；仍须遵守批次审批与运行门禁 |
| `${VGAME_CONFIG_DATAS}` | Vgame 正式配置源 Excel | 仅在用户明确批准具体批次后写入 |
| `server_json`、客户端导出物 | Luban 生成物 | 禁止直接修改 |

## 标准链路

```text
01_源表 + 03_沉淀MD
→ 04_数值文档生成与 05_验算核算
→ Vgame配置映射总表（全量 Schema，只读刷新）
→ 按用户指令生成一个配置草案批次
→ 类型/枚举/Bean/引用/公式/影响范围预检
→ 生成独立正式配置粘贴包（按正式字段顺序、纯值、精确目标坐标）
→ 用户按批次明确批准、驳回或要求修改
→ 批准后备份并写入 Datas 正式源表
→ Luban 导出 + 配置规则检查 + 生成物差异核对
→ 回写落地回执；若数值裁决变化，同时回写所属 MD
```

## 映射总表定位

- 文件：`00_总览/Vgame配置映射总表.xlsx`
- 生成器：`02_AI规则/generate_vgame_config_mapping.py`
- 机器报告：`05_验算核算/vgame-config-mapping-report.json`
- 人读报告：`_reports/P6_Vgame配置映射总表_生成与审计.md`
- Schema 来源：`${VGAME_CONFIG_DATAS}/__tables__.xlsx`、`__beans__.xlsx`、`__enums__.xlsx` 和注册输入工作簿。
- 总表只复制字段结构和约束，不复制正式配置的数据行。
- `配置草案`、`审批记录`、`落地回执` 初始为空；后续按批次填写。

## 工作簿分层

| Sheet | 内容 | 可否人工维护 |
|---|---|---|
| `使用说明` | 当前 Schema 快照、覆盖情况、权威边界和操作入口 | 否，随 Schema 刷新 |
| `逻辑表清单` | `__tables__` 中全部逻辑表 | 否 |
| `表输入关系` | 逻辑表到物理工作簿与 Schema Sheet 的映射 | 否 |
| `逻辑字段字典` | 合并后的逻辑字段及多输入冲突状态 | 否 |
| `物理字段来源` | 每个输入文件实际字段、类型、主键、公式与约束 | 否 |
| `Bean与字段` | `__beans__` 复合结构 | 否 |
| `Enum与枚举项` | `__enums__` 枚举约束 | 否 |
| `公式字段摘要` | 公式/常量混合、外链样式公式和自动写入风险 | 否 |
| `未注册工作簿` | Datas 中存在但未被 `__tables__` 消费的 Excel | 否，只做审计 |
| `Schema异常与门禁` | 缺失、歧义、Schema 冲突和阻断项 | 否 |
| `模块映射` | 数值模块、MD 与目标配置表的关系 | 可维护人工映射列 |
| `配置草案` | 待审批的字段级变更 | 可按批次维护 |
| `审批记录` | 用户对批次的明确决定 | 只记录真实人工决定 |
| `落地回执` | 正式写入、导出、验证与回滚证据 | 正式落表后填写 |
| `工作流门禁` | 状态机和硬性禁止规则 | 否 |

## 配置批次状态

```text
DRAFT
→ READY_FOR_REVIEW
→ APPROVED
→ APPLIED
→ EXPORTED
→ VERIFIED
```

旁路状态：

- `REJECTED`：用户驳回，禁止写入正式配置。
- `NEEDS_REVISION`：需要修改草案，修改后重新提交审批。
- `SUPERSEDED`：被新批次替代，禁止继续执行旧批次。
- `MANUAL_REQUIRED`：涉及公式单元格、插入/删除行、Schema 迁移或编辑器资产，必须人工处理。

## 每次模块配置指令的执行规则

1. 从用户指定模块、`01_源表` 和对应 `03_沉淀MD` 确认数值依据与稳定参数 ID。
2. 从映射总表定位逻辑表、物理工作簿、Schema Sheet、主键、字段、类型、Bean/Enum 和导出分组。
3. 只读取正式配置中与目标主键相邻的必要数据，生成字段级差异；不得把全表业务数据复制进映射总表。需要整表值交付时，另建 `04_数值文档/配置粘贴包`，不得塞回 Schema 镜像。
4. 在 `配置草案` 新建唯一批次，写清旧值、建议值、转换/舍入、引用影响、验证方式与风险。
5. 完成预检后生成独立粘贴包：字段顺序必须与正式表一致，明确“复制范围 → 正式范围”，复制区禁止公式；完整值、条件值和阻断项必须分层。
   - 对一个完整系统，粘贴包必须覆盖数值目标、属性承载、生成池、道具、关卡、常规/首通 Drop、UI 预览、入口/解锁、消耗/回收与边界排除；只交付其中一段时必须显式命名为“子包”，不得称为全部配置。
6. 完成预检后把批次置为 `READY_FOR_REVIEW`，向用户展示完整影响矩阵和可粘贴文件。
7. 只有用户明确批准该批次版本，才能记录 `APPROVED`。口头讨论、模糊同意或旧批次批准不能复用。
8. 正式落表前再次读取 `data_only=False` 的目标单元格和当前 Schema；草案、粘贴包与正式配置漂移时立即停止并重新审批。
9. 写入完成后执行导出、检查和差异核对，最后填写 `落地回执`；未验证不得标记 `VERIFIED`。

## 正式配置硬门禁

- 未获得当前批次的用户明确批准：不得写 `${VGAME_CONFIG_DATAS}`。
- 未获得用户对 SVN 工程写入的明确授权：SVN 工作副本保持只读。
- 不得直接修改 `server_json`、`TempDatas` 或客户端生成配置。
- 不得覆盖任何公式单元格；每次写入前必须用 `data_only=False` 复查目标单元格。
- 不得自动 `insert_rows`、`delete_rows`、`insert_cols` 或 `delete_cols`。
- 对 `Drop_dungeon.xlsx` 等公式敏感表，新增多行的标准操作是：人工预建行 → 从邻接正式行下拉公式 → 仅粘贴纯值列 → 检查公式/权重/外键。
- 需要新增公式驱动行、修改 Schema、修改 Bean/Enum 或注册新表时，单独进入 `MANUAL_REQUIRED` 或 Schema 迁移流程。
- 写入前必须备份目标源工作簿；写入范围只能是获批批次中的安全单元格。
- 写入后必须验证源表可打开、Schema 行未破坏、主键/引用有效、Luban 导出成功、生成物可解析且差异符合批次。
- 配置草案中的数值若形成新的设计裁决，必须同步回写所属 MD；不得让 Excel 草案成为第二份参数权威。
