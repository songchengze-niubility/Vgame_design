## 1. 状态记录规则

每个系统至少同时记录：设计生命周期、运行/发布状态、落地证据状态。`Design Doc = Draft` 不等于系统未实现；配置或代码存在也不等于当前对玩家开放。

## 5. 项目级缺失登记

| ID | 缺失能力 | 影响 |
|---|---|---|
| G-001 | 正式战斗总纲 | 基础规则、模式差异、配置入口和验证标准散落 |
| G-002 | 正式玩法到实现矩阵 | LevelType、Intent、GameMode、SceneData、结算无法一眼追通 |
| G-003 | 版本/活动/AB/灰度/Hotfix 台账 | 无法可靠判断 LIVE、回滚范围和跨版本兼容 |
| G-004 | 项目级 UI 信息架构与红点规范 | 入口、跳转、提示优先级和异常恢复不统一 |
| G-005 | 数据/埋点/经济监控/战斗指标总纲 | 模型与实机缺少持续回证 |
| G-006 | 好友/聊天、叙事/本地化、合规/客服正式文档 | 项目知识覆盖有域但缺事实资产 |

关闭任何条目时都必须记录：裁决人、日期、生效版本、替代来源、受影响文档/配置/代码、验证证据和回滚方式。
