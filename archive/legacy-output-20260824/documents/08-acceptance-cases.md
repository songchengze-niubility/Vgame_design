# 项目级策划知识框架验收用例

## AC-01 系统模块内部一级分类

- Given：查看玩家系统知识树。
- When：检查其直接子域。
- Then：只有战斗内 `BI` 与战斗外 `BO`；项目支撑层 `XS` 不属于玩家系统。

## AC-02 战斗外细分完整

- Given：查看 `BO`。
- When：检查二级域。
- Then：至少覆盖玩法、养成、获取、经济、任务留存、商业化、社交、引导解锁、版本运营、战斗外 UI。

## AC-03 玩法双域

- Given：任一主线、副本或竞技玩法。
- When：归类其规则。
- Then：入口/周期/成本/奖励归战斗外壳层，地形/敌人/模式/胜负归战斗内实例；两者可由同一玩法身份关联。

## AC-04 成长闭环

- Given：任一养成系统。
- When：追踪资源来源、成长转化和验证场景。
- Then：能从供给追到属性/机制，再追到至少一个正式战斗验证玩法。

## AC-05 经济闭环

- Given：任一关卡型玩法。
- When：检查奖励。
- Then：首通、重复、概率/权重、周期奖励、UI 预览与真实入账均有责任归属；视觉掉落不改变结算。

## AC-06 状态分轴

- Given：大秘境、通行证、公会、收容物或专武。
- When：查询状态。
- Then：分别返回设计生命周期、运行/发布状态、落地证据；未裁决冲突不会被压成单一“正式”。

## AC-07 文档全覆盖

- Given：当前 `design/**/*.md`。
- When：执行构建和验证脚本。
- Then：52/52 文档有源哈希、Understand 节点、主域和次域映射；无未知领域引用。

## AC-08 战斗事实防漂移

- Given：查询护甲、Skill Action、Buff Effect、Buff 数据或 AI。
- When：框架提供当前事实。
- Then：分别得到 24000、73 类、15 类、Excel 元数据+二进制行为、行为树已实现，并能回到真实证据。

## AC-09 配置路径

- Given：查询当前服务端 JSON 生成目标。
- When：按证据优先级回源。
- Then：返回 `Config/GameConfig/server/json`，并把 `server_json` 标为旧文档漂移。

## AC-10 知识缺口

- Given：某域没有正式 Design 或 LIVE 证据。
- When：查看框架。
- Then：该域仍在项目知识树中，但明确显示缺口，不生成虚构规则或上线结论。

## AC-11 变更影响

- Given：角色、玩法、奖励或开放条件发生修改。
- When：使用跨域影响矩阵。
- Then：能列出必须复核的战斗内、战斗外、配置、数值、UI、数据和 QA 邻域。

## AC-12 写入边界

- Given：框架尚未获用户批准。
- When：交付本轮结果。
- Then：只写 `output/项目级策划知识框架` 和 Understand 派生图，不移动 `design/`，不修改真实 SVN 配置/代码。

## AC-13 分层人工审核

- Given：用户打开项目级框架评审批注台。
- When：用户审核 BI、BO、XS 一级结构，并选择“认可本层及其领域”。
- Then：主进度只按 3 个一级结构计算；该层未评审领域获得可追溯的批量结构结论；160 条专家明细和后续专项问题不计入本轮完成度，且 `itemReviews` 不会被批量写入事实认可。

## AC-14 项目与专业模块入口

- Given：用户打开当前日常知识库。
- When：查看主导航和项目总览。
- Then：先看到 Vgame 项目定位、核心循环与系统版图；主知识入口为系统、战斗、数值和关系，不以 BI/BO/XS、审计或评审流程作为首屏目录。

## AC-15 系统分层

- Given：用户进入系统模块。
- When：浏览系统分类和具体系统。
- Then：系统先分战斗内/战斗外；战斗外再分玩法、养成、周边系统；每个具体系统至少显示摘要、状态提示和直接关系。

## AC-16 战斗与数值边界

- Given：用户分别进入战斗和数值模块。
- When：查看知识树。
- Then：战斗以“战斗规则 / 角色设计”为两个稳定入口；数值对齐框架 v2 的共享底座、养成、战斗、经济、节奏与源表—沉淀—文档—验算—配置交付链；两者不会互相复制完整规则或参数。

## AC-17 易调用与易评论

- Given：用户要查找或修订一个具体系统。
- When：使用全局搜索或稳定深链打开详情，并填写评论。
- Then：无需浏览 28 个领域或 160 条专家原子即可看到知识路径、摘要、状态和关系；评论以稳定 ID 暂存并可导出，旧评审材料只从治理入口进入。

## AC-18 具体系统不是目录摘要

- Given：用户从“系统 → 战斗外 · 玩法”打开主线。
- When：进入 `#system/SYS-OUT-GP-01`。
- Then：显示独立系统正文，而不是摘要抽屉；正文至少包含总览、核心流程、系统规则、条件、奖励、异常、UI、配置、关系、证据和待确认章节。

## AC-19 目标规则与当前事实分层

- Given：主线的目标设计、当前 Excel 和运行版本存在差异。
- When：查看状态轴和任一规则卡。
- Then：目标规则、本机工作副本事实、验收口径和 Production/LIVE 不确定性分开展示；工作副本带核对日期与环境说明，未裁决冲突不会被写成“已上线”或“正式完成”。

## AC-20 规则级评论可追踪

- Given：用户认为某条主线规则需要修改。
- When：点击该规则的“评论此规则”，填写并保存意见，再刷新页面或导出评论。
- Then：评论记录包含稳定规则 ID、父系统 ID、对象类型和正文 revision；刷新后恢复，导出后可据此精确回写。

## AC-21 详情完整度不虚报

- Given：45 个系统中仅主线已完成结构化正文。
- When：查看系统目录和自动验证报告。
- Then：主线显示“完整正文”，其余显示“摘要索引”，覆盖率为 1/45；验证通过不被解释为 45 个系统规则已全部完成。

## AC-22 主线章节等级门槛可追踪

- Given：玩家查看序章、第一章或第二章，或查看第三至第七章中的任一章节。
- When：系统通过 `ChapterLevel.Unlock → Unlock` 计算章节开放状态。
- Then：ChapterId 10000～10002 无条件开放；10003～10007 分别在玩家等级达到 Lv24/Lv28/Lv31/Lv33/Lv35 时开放，低于门槛时锁定。章节入口不再额外检查前章末关。配置证据为 UnlockId 201～205，运行时证据为 `LevelSystem:GetChapterIsUnlock → ConditionSystem:GetIsUnLock`，生成物中 `chapterlevel.lua` 与 `unlock.lua` 必须保持同值。
