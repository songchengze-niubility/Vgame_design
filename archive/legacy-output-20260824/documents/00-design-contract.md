# Vgame 项目级策划知识框架需求契约

## 1. 目标

建立一套能够代表 Vgame 项目整体策划知识、可以轻松调用和修改的分层知识库，用于：

- 先说明整个项目的定位、体验、核心循环和系统版图。
- 以 `系统 / 战斗 / 数值` 作为三个专业知识模块，而不是把系统事实、审计和治理平铺成清单。
- 在系统模块内先分战斗内与战斗外；战斗外继续分玩法、养成和周边系统。
- 由战斗模块集中说明战斗规则与角色设计。
- 由数值模块对齐“数值框架 v2”的共享底座、养成、战斗、经济、节奏及交付链。
- 用有类型的关系说明系统之间及系统—战斗—数值之间的输入、输出、供给、消耗、验证和替代关系。
- 把状态、证据、冲突、评审和验收降为治理附录，避免污染日常知识入口。

## 2. 用户已确认的核心结构

### KF-R001：项目先于模块

知识库第一层先介绍整个 Vgame 项目，包括项目定位、核心体验、核心循环、系统版图，以及系统、战斗、数值三个专业模块的职责。

### KF-R002：系统模块的玩家系统分类

系统模块内部首先分为：

1. **战斗内系统**：从战斗实例加载到胜负成立并触发结算的实时系统。
2. **战斗外系统**：战斗实例之外负责玩法组织、成长、获取、留存、社交和运营的系统。

战斗外的主分类为：

- 玩法。
- 养成。
- 周边系统；在需要时继续用获取、经济、任务留存、商业化、社交、引导解锁和 LiveOps 标签细分。

### KF-R003：战斗模块

战斗模块的两个稳定入口是：

1. 战斗规则。
2. 角色设计。

敌人、技能、Buff、关卡、玩法局内变体和反馈结算均作为这两个入口下的具体内容继续下钻。

### KF-R004：数值模块

数值模块对齐 `${VGAME_SOURCE_DOCS_ROOT}/框架v2`：共享底座之下保持养成、战斗、经济、节奏四条主数值链；源表与沉淀 MD 拥有事实和参数，数值文档、验算与配置镜像属于派生交付。

### KF-R005：框架先于细节

总览只维护结构、摘要、关系和权威入口，不在首页复制所有系统正文；但具体系统的详情页必须真正包含可执行的系统规则、流程、条件、奖励、异常、UI、配置契约、关系、证据与待裁决问题，不能用一段摘要冒充策划案。具体参数仍回到数值与真实配置权威源。

### KF-R006：治理附录

配置管线、状态、证据、冲突、图谱、评审、验收和发布治理保留，但不作为与系统、战斗、数值并列的日常知识入口。

### KF-R007：具体系统拥有可评论的完整正文

每个具体系统保留稳定系统 ID，并继续拆出稳定的规则、流程、条件、奖励、异常、UI、配置、关系、证据和待确认条目 ID。系统详情必须并排区分目标设计、本机工作副本源表事实、Production/LIVE 状态和治理冲突；评论可绑定整个系统或任一稳定条目，后续修订不因正文改写而更换 ID。

## 3. 分类原则

1. **先判断专业模块，再判断具体分类。** “系统 / 战斗 / 数值”是阅读视图；“战斗内 / 战斗外”是系统模块内部的玩家系统分类。
2. **同一事实只保留一个权威入口。** 系统讲职责和关系，战斗讲运行规则，数值讲参数与验证。
3. **玩法保留一个系统身份，但连接两种规则视图。** 外壳在战斗外系统，实例规则在战斗模块。
4. **经济不作为孤立产出表。** 奖励和消耗归属具体玩法/系统，经济总账只做跨模块汇总和风险校验。
5. **养成与战斗必须通过属性/机制输出和验证玩法建立转化链。**
6. **图谱只作导航。** Understand 摘要和边不替代真实策划、沉淀 MD、源表或运行时证据。
7. **状态使用多轴表达，但状态不占主导航。**

## 4. 本期范围

- 项目总览、系统、战斗、数值和关系五个日常知识入口。
- 战斗内系统，以及战斗外玩法、养成和周边系统的简单项目级分类与说明。
- 战斗规则和角色设计的框架入口。
- “数值框架 v2”的权威链与养成、战斗、经济、节奏结构。
- 具体系统的输入、输出、战斗接口、数值接口和上下游关系。
- 以主线为首个完整正文样板，建立可扩展到全部系统的详情 schema、生成链、规则级评论和完整度门禁；未完成正文的系统必须明确标为“摘要索引”。
- 现有 `design/**/*.md`、数值沉淀、配置链和 Understand 图谱继续作为证据与下钻入口。
- 配置和生产链只建立知识入口，不在本期修改真实 Excel、JSON、代码或 SVN。

## 5. 非目标

- 不在本期裁决每个数值、概率、奖励数量或字段值。
- 不把每份 Design Doc 改写成最终版本。
- 不覆盖 `design/` 现有文件。
- 不把废弃、临时或尚未开放的系统重新声明为当前线上系统。

## 6. 交付物

- `knowledge-base/README.md` 与项目总览、系统、战斗、数值、关系、治理附录 Markdown。
- `knowledge-base/index.html` 日常浏览与评论入口。
- `knowledge-base/knowledge-model.json` 维护稳定导航 ID、摘要和关系模型；`knowledge-base/system-details/*.json` 维护具体系统结构化正文；`knowledge-model.js` 与 `systems/*.md` 为生成物。
- 保留原系统领域矩阵、文档映射、状态冲突和专项审查，作为治理附录。
- 新结构的评审与验收用例。

## 7. 风险与门禁

- 风险级别：`HIGH`，因为框架会影响全项目后续归类和决策。
- 当前用户消息已经确认 KF-R001～KF-R007 的方向；v0.3 已用主线验证完整正文结构，但完整度目前为 1/45，仍需用户确认样板深度后再全量扩展。
- 新结构确认前不把框架写回 `design/`，不宣称最终验收通过。
